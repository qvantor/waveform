# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Waveform is an experimental browser wavetable synth (TypeScript + Web Audio API, React 18). It is an Nx 14 monorepo with one app (`apps/waveform`) and four libs (`libs/math`, `libs/rxjs-react`, `libs/ui-kit`, `libs/preset-schema`), plus Netlify serverless functions in `netlify/` and a Postgres database for presets. Deployed to Netlify.

## Commands

- `npm start` — runs `netlify dev` (functions on :8888) and the Nx dev server (:4200) together. The dev server proxies `/.netlify/*` and `/api/*` to :8888 (`proxy.conf.json`), so wavetables and presets only work when both run.
- `npm run certs` — generates `.certs/` (gitignored) with mkcert for localhost and the current LAN IPs. `netlify dev` serves HTTPS with it (`[dev.https]` in `netlify.toml`) and fails to start without it; run `mkcert -install` once to trust the local CA.
- `npm run client:start` — frontend only (`nx serve`); wavetable list/download requests will fail.
- `npm run build` — production build to `dist/apps/waveform`.
- `npm run worklets` — bundles the audio worklet modules (reverb, limiter, distortion, wavetable-osc) and the Web Worker of the wavetables (`wavetable-worker`, a classic worker: the bundle has no import/export), one `name=path` entry each, with esbuild into `tmp/worklets/` (served as `assets/worklets/` via the `assets` of `apps/waveform/project.json`). `build` runs it with `--minify`, `client:start` runs it once and then in watch mode next to `nx serve`.
- `npx -y -p playwright@1.50.1 node scripts/bench-osc/run.mjs` — the manual benchmark of the wavetable oscillator against a native `OscillatorNode` in Chromium, WebKit and Firefox (sound criteria, CPU, delivery, memory; `scripts/bench-osc/README.md`). Playwright is not a dependency (knip ignores it); the 3 tables come from S3 with the keys of `.env` (the helpers shared with bench-perf are in `scripts/bench-common.mjs`); report in `tmp/bench-osc/report.md`.
- `npx -y -p playwright@1.50.1 node scripts/bench-perf/run.mjs [--against=<ref>] [--only=S5,L1,L3,dsp|cpu|latency] [--runs=5] [--browsers=chromium,webkit] [--update-baseline]` — the perf suite (`scripts/bench-perf/README.md`), only what needs a real browser: the perf build (`npm run build:perf`, cached) in headed Chromium (WebKit on request), S5 (the heavy patch, 12 notes: cycles of the audio thread and memory from Instruments, `xcrun xctrace`, macOS + Xcode; render quanta, dropouts; 5 runs), L1 and L3 (50 notes through the keyboard, alone and over 8 held notes: latency to the voice and to the output from the test hook) and the DSP in Node. Regressions only in an A/B run: `--against=<ref>` (`main`; `HEAD` for uncommitted changes; a clean tree against `HEAD` is an A/A check) checks the commit out in `tmp/bench-perf/against/<sha>` (a git worktree, `node_modules` linked, its perf build made once, `reference.mjs`) and alternates its runs with those of the working tree in one session (S5 A B B A …, L1/L3 in 5 sessions of 10 notes a side, the DSP samples in one process; ~7 min): a one-sided Mann–Whitney test and a shift of the median over a threshold fail (exit 1, `verdict.mjs`), as broken invariants do. Two sessions of the same code differ by up to ~10% (S5, the DSP), so `scripts/bench-perf/baselines/<machine>.json` (`--update-baseline`, the raw values and the conditions of its run) only warns of drift; budgets warn; a run without `--against` takes ~3 min; report in `tmp/bench-perf/report.md`. The rest of the old scenes (the chain latency, the work of the voices and the effects, the note-on work, the memory of the tables, leaks) are deterministic Jest specs in CI (README: what moved to the specs).
- `npm run build:perf` — the production build with the test hook (`dist/apps/waveform-perf`): the `perf` configuration of `apps/waveform/project.json` swaps `app/perf/perf-hook.tsx` (nothing) for `perf-hook.perf.tsx` (`window.__waveformPerf`, `perf-api.ts`) and takes its own worklets (`tmp/worklets-perf`). ## Architecture

### State: `rxModel` (libs/rxjs-react)

All app state and audio logic live in RxJS "models", not React state. The pattern:

```ts
const model = (deps) =>
  rxModel((initial) => ({ $foo: new PrimitiveBS(0), audioNode, ... }))  // state: BehaviorSubjects + Web Audio nodes
    .actions((model) => ({ setFoo: (v) => model.$foo.next(v) }))
    .subscriptions((model, actions) => [ ...rx subscriptions wiring state to audio... ])
    .plugins(urlSnapshotPlugin({ modelToSnap, applySnap }))
    .destroy((model) => { ... });

export const { ModelProvider: FooProvider, useModel: useFoo } = rxModelReact('fooModel', model);
```

- Each builder call returns a new immutable factory; `init` runs actions, subscriptions, and plugin `onInit`; unmount runs `destroy`, unsubscribes, and plugin `onStop`.
- `rxModelReact` wraps a model in a React context. `<FooProvider initial={...} {...deps}>` takes the `initial` value plus dependency props (other models' `[model, actions]` tuples); `useFoo()` returns `[model, actions]`.
- Components read observables via `useBehaviorSubject($x)` / `useObservable`. BehaviorSubject helpers: `PrimitiveBS`, `ArrayBS`, `ObjectBS`. Observable names use a `$` prefix.
- Dependency injection is done through provider nesting, so provider order matters. The tree in `apps/waveform/src/app/synth/index.tsx` defines it: InputController → SynthCore → Envelopes → Modulation → Oscillator1/2 → MidiController → Filter → Synth (the filter in its voices) → Fx (follows the synth's last note) → KeyboardController → Presets.

### Audio graph (apps/waveform/src/app/synth/common/modules)

- `synth-core.ts` owns the single `AudioContext` and its wavetable oscillator (`wavetables`, `createWavetableEngine`): `preGain → fxIn → [fx chain] → fxOut → masterGain → masterLimiter → destination` (the filter is in each voice). `$masterGain` is linear, the Master knob (`master-handle.tsx`) shows it in dB from −40 (silence) to +12: above 0 dB it drives the limiter. The header analysers tap `output` (the limiter's output).
- The master limiter (`synth/common/limiter/`) is the last stage, after the master volume. `limiter-dsp.ts` is the pure signal processing (tested offline): a stereo linked brickwall at −0.5 dBTP with a 4× true peak detector (`true-peak.ts`, polyphase Kaiser sinc whose phase 0 is the input itself), 2 ms lookahead, the needed gain held for 20 ms (the gain never moves inside a bass wave), a fast (50 ms) and a slow (0.5 s) release envelope (short peaks let go fast, dense parts slowly, no pumping between their notes; once the sound has needed less than the slow one for 250 ms it lets go at the fast rate, down to what the sound still needs) and two moving averages over the lookahead (S-shaped attack). The detector skips the interpolation while the last 32 samples are below the ceiling / `TRUE_PEAK_BOUND` (−8.6 dBFS: no point between them can reach the ceiling), and sums its 3 phases in one pass over the history, so quiet parts cost 0.2% of a core (about 0.6% while limiting, the native compressor 0.15%) and the output is the same to the bit. No sample goes over the ceiling, the true peak of band-limited sound stays under 0 dBFS (the 4× grid reads at most cos(π·f/4) low), below the ceiling, once released, the sound passes bit for bit, delayed by `latency` (2.3 ms at 48 kHz). `limiter.worklet.ts` registers the processor, `master-limiter.ts` loads it with `createWorkletFx`; while it loads, without AudioWorklet or after it failed the master goes through the old DynamicsCompressor (`FALLBACK_LIMITER`: hard knee at −4 dB, 250 ms release, its makeup gain taken back by `compensation`), which overshoots on the onset of dense unison chords.
- The `fx` model (`synth/fx/`) wires the FX rack between `fxIn` and `fxOut`. Effects are defined in `FX_REGISTRY` (`fx/effects/`, params and ranges from `FX_PARAMS` in `libs/preset-schema`). `createFxSlot` wraps each one: `mix` is a crossfade (`mixGains`: 0 only dry, 1 only wet; equal power for delay and reverb, both at −3 dB at 0.5; linear for a core with `linearMix`, the distortion: its wet signal is the dry one reshaped and in time with it, they add up like one sound and equal power would be 3 dB louder in between; the default of a fresh effect is per type, `FX_MIX_PARAMS`: the distortion is all wet, delay and reverb 0.3), bypass passes only the dry signal at full level; a core with `latency` (the distortion) gets its dry signal delayed as much (`dryDelay`), so the timing never jumps and the mix doesn't comb filter. The chain is the added effects in `$order`; adding an effect type means a registry entry plus its preset schema. `FX_TYPES` is the default chain order (distortion, delay, reverb); `normalizeFxOrder` puts a type missing from a saved order (saved before it existed) at its default place, before the first effect that follows it in `FX_TYPES`, not at the end.
- The reverb runs in an AudioWorklet: `reverb-dsp.ts` is the pure signal processing (16-line FDN, tested offline with impulse responses), `reverb.worklet.ts` registers the processor, `reverb.ts` creates the `AudioWorkletNode` once `loadWorklet` has added the module and posts param changes to it. The worklet modules register their processor with `registerStereoProcessor` (`fx/effects/stereo-processor.ts`: the AudioWorkletGlobalScope declarations, a mono input feeds both sides, a disconnected one is silence, `stop` ends it), their nodes are created with `STEREO_WORKLET_OPTIONS`. A worklet module must not import `@waveform/ui-kit`, `@waveform/preset-schema` (zod) or anything touching `window`/`document`. The synth core adds the limiter and the wavetable-osc modules itself, so specs that count `addModule` calls count only their module (`workletLoads` in `test-utils`). In a hot loop, don't chain calls per sample that return doubles through closures or polymorphic sites: V8 boxes every such result (a HeapNumber), so the audio thread makes garbage and burns CPU; run each stage over the block in typed arrays (the distortion, `createBiquad().processBlock`, its state is a `Float64Array`).
- The distortion runs in an AudioWorklet too (`distortion.ts`, `distortion.worklet.ts`): `distortion-dsp.ts` (tested offline, aliasing included) drives the input (0 to 12 dB: more folds back audibly on high notes at 4×) into the curve of the mode 4× oversampled (`oversampler.ts`: polyphase windowed sincs, `fir.sincPhase` in `libs/math`, linear phase, `DISTORTION_LATENCY` = 32 samples; the decimator is the one of the true peak detector, cut at the nyquist, the interpolator is cut at 0.9 × the nyquist, flat up to 0.4·fs: cut at the nyquist it passed half of the images of the partials just below it, which an oscillator plays, and the curve mixed them into inharmonic tones, so its phase 0 is not the input itself), × its makeup gain (`distortion-makeup.ts`: a table per mode over the drive that keeps the RMS of a reference sine of `REFERENCE_PEAK` 0.5, a note at the fx input; 1:1 with the drive while the reference is unclipped, then it levels off towards −9 dB, −7.1 dB soft and −8 dB hard at 12, so louder sounds come out quieter and quieter ones louder: the curve compresses), then the tone lowpass (at the top of its range, `TONE_OPEN`, it is faded out: the wet keeps the phase of the dry), the level (a trim on top of the makeup) and a DC blocker (one pole at 5 Hz, `createDcBlocker`: the curves are odd, but an asymmetric wave, a narrow pulse, gets DC from them, which would eat into the headroom of the limiter; the tests of the gains undo it, `unblock`); drive, makeup, level, tone and a new mode (a crossfade of the curves, each with its makeup; the mode changed back during a fade turns it around where it is) glide. The gains go on the oversampled points, before the decimator, so a crossfade never mixes points with and without them. The chart shows the curve of the mode at the drive within ±1, without the makeup and the level (they only scale the output). The modes are `DISTORTION_MODES` (`distortion-modes.ts`: soft clip = tanh, hard clip): the `mode` param is an index into it, so new modes are appended and `FX_PARAMS.distortion.mode.max` raised; a curve is odd, within ±1 and has the slope 1 at 0 (bitcrush would need a state of its own). It has no loops: `setActive` does nothing; once its input has been silent longer than the oversampler rings only the tails of the tone and the DC blocker are rendered (about 0.7 s after a DC-heavy sound, at 0.15% of a core), then the worklet clears its state and skips the blocks. Each stage runs over the block (`oversampler.up/down` and the `shapeBlock` of the mode take typed arrays; each mode has its own loop, so its curve is inlined), the output is the same to the bit as sample by sample. It costs about 1% of a core while playing (soft clip 1.1%, hard clip 0.95%, reverb 2.6%), 0.05% unused.
- A worklet effect builds on `createWorkletFx` (`fx/effects/worklet-fx.ts`: loading, input → node → output, `$status`, `retry`, `destroy` posts `stop` to the processor). Without AudioWorklet (http on a LAN IP, old Safari) or when its module fails, the app still works: the fx model keeps the effect out of the chain (it stays `added` in the snapshot), and the Effects list shows why under its name. An unsupported effect can't be added, an added one that can't be used can still be removed, a failed one loads again on Retry or when it is added. Until an effect is `ready` (also while it loads) its slot passes only the dry signal and is inactive.
- The oscillators run in an AudioWorklet (`synth/common/wavetable/`), there is no native fallback: without AudioWorklet, Worker or MessageChannel the synth doesn't play and each oscillator shows why over its wave (`OscillatorStatus`, Retry for a module that failed). `wavetable-engine.ts` (one per context, in the synth core): `$status` loading/ready/unsupported/failed (the module, the worker or the store) and `retry` (as `createWorkletFx`), the store node (`STORE_PROCESSOR`, 0 inputs, 1 output never connected: 0/0 is not allowed), the worker (`wavetable.worker.ts` → `wavetable-builder.ts`) and a MessageChannel between them: `setTable(id, frames)` copies the frames into Float32Arrays transferred to the worker, the worker builds the levels (`wavetable-mipmap.ts`, a newer version of a table replaces a waiting one) and transfers them to the store; the store (`createTableStore`, one per AudioWorkletGlobalScope, refcounted versions) acks `{stored, version}` and hands the buffer of a version no voice plays back to the worker (reused for a table of the same size: the audio thread never collects 64 MB). Tables are kept and sent again after a retry, versions only grow. `createVoice` gives the node of a note, null until ready (a note played meanwhile isn't played later). For the perf suite and the specs (the perf build and Jest, under `__PERF__`): the engine reads the acks (`pending()`: tables whose latest version isn't in the store yet) and `stats()` asks the store (`{stats: true}`: versions and bytes held, voices alive and their unison, samples played from mix tables or directly, mix builds and refusals, mix tables allocated and their bytes, counted in a `Float64Array` of `createVoiceShared`) and the worker (pending tables, freed-buffer pool, build ms); a voice with `processorOptions.trace` posts `{started, scheduled}` (frames) once, the synth traces voices only while its `$voiceStarts` is observed.
- Levels (`wavetable-mipmap.ts`, `wavetable-levels.ts` has the layout without imports, so the worklet bundles no FFT): a third of an octave apart on the grid of Chrome's PeriodicWave (`levelBase`: harmonics up to 1024 · 2^(−r/3), at most the frame's 1023, then a silent level of 1 sample), each 32 samples per cycle of its highest harmonic long, 512..4096 (`levelLength`), 1 guard sample before a frame and 2 after it; DC and the nyquist bin dropped, every level of a frame normalized by the peak of its full band (as createPeriodicWave), phases kept, frames of 16..2048 samples, `MAX_FRAMES` 256 (≈ 63.6 MiB). Building 256 frames takes ~150 ms (Firefox ~300).
- The voice (`wavetable-osc-dsp.ts`, tested offline; `wavetable-osc.worklet.ts` registers it and the store): one node per note plays both oscillators (null in `processorOptions.osc`: off for the note) with their unison voices into one stereo output. Params (`wavetable-osc-params.ts`, a-rate): `frequency` (the note, portamento glides it), `gate` (1 the key is held, 0 starts the release of ENV 1 at that sample, below 0 fades a stolen voice out in 5 ms; automation, not a message: messages arrive late), per oscillator `position` (share of the table, frame k of N at k/(N−1)), `detune` (cents: 1200·octave), `spread` (cents over the unison), `gain`. `processorOptions` (what is read at the note on): the table id, the unison (1..8, one voice at spread 0 unless a route raises the spread), `phase`/`phaseRand` (shares of a period), `envelopes` (ENV 1–3) and `envStart` (in legato the start of the phrase), `routes` and `filter`. The volume is ENV 1 (`envelope-block.ts`, exact to the sample, the release from the level reached); the voice ends where ENV 1 is back at 0 and posts `ended`. Routes (`voice-modulation.ts`) replace the params they move by base + Σ amount × level (base × 2^Σ for a log one), clamped to the knob's range; while every envelope a param follows is in a flat stage and its amounts don't glide it is one value (the voice stays on its mix table), an envelope no route reads is not rendered, a changed route glides in 10 ms (`{ routes }` message). The filter (`voice-filter.ts`, `{ filter }` message, null: off) runs after the oscillators and before ENV 1, coefficients of `coefficientsInto` (`@waveform/math/biquad`, an alias that keeps the FFT out of the bundle) worked out every 32 samples only when a value changed, its knobs glide ~10 ms; a moved param is not copied: its values go into an override the voice reads instead of the param (`Osc.moved` per oscillator, `moved` of the filter, through the `ParamAccess` of each target; by a computed name V8's accesses go megamorphic). Every AudioParam of the node costs every block even without automation (~1.5% of a held note in Chrome each), so values read once are options. Unison voice j is detuned by spread·(j/(n−1) − ½); the middle one of an odd count both channels, the others alternately left and right from the lowest (a voice and its mirror on opposite sides: the channels mirror each other, their sum is centred on the note); each at 1/√⌈n/2⌉. Every voice starts at `phase` plus a random share of the period up to `phaseRand` (0: all in phase, their beats sweep through the spectrum and n voices are louder at the onset; 1: any phase, steady, the power of one voice); at `phaseRand` > 0 the voices fade in over 1.5 ms. Pitch → level as Chrome does (`1 + 3·log2(base·f/nyquist)`: floor(x) crossfaded with the next one), position → frames k, k+1 morphed linearly; a changing pitch or position is worked out every 32 samples and interpolated. Levels are read linearly; while pitch, position and table stay (from the second block) each unison voice sums the 2 frames × 2 levels it reads into a mix table as long as the native table (4096, 16384 above 88.2 kHz; shorter levels 6-point Lagrange interpolated into it once), built under a per-block budget (200k multiply-adds across the scope's voices), buffers pooled: a held note costs ~0.8× a native oscillator in Chrome with native aliasing. A param is constant when its array has one value or all equal (a silent input still gives 128). A new version of a table is crossfaded into over 10 ms. Shared block buffers for all voices of the scope; Float32 channel buffers copied once into the outputs (writing the outputs many times was slow in WebKit).
- `oscillator.ts` holds the frames (`$waveTable`), the Wave position `$position` (frames 0..N−1; the knob steps by whole frames, the voices morph a fractional one, from a preset or a modulation; the editors work on `frameIndex` = the nearest frame, choosing one sets it), `$morphWave` (the chart: one period edge to edge, phase 0 to 360°), `$osc` (unison, detune, octave, phase, phaseRand) and `$gain`; the Wave frame, Phase and Phase rand are shown in a strip under the chart, on its background (`oscillator/components/wave/wave-info.tsx`, `DragValue` of ui-kit: pressed and dragged, right or up raises it, Phase goes around), while Phase or Phase rand is held the chart shows the phase on the wave and the band [phase, phase + rand) the voices start in, wrapped as they do (`phase-overlay.tsx`); `$params` is the base of the voice params from them. It sends its table to the engine under its `id` (a new table at once, edits of its frames at most every `TABLE_THROTTLE` 100 ms), removes it on destroy, and has a mod bus (`buses`, a GainNode) per param: `connectBus(param, source)`/`disconnectBus` for a global source (LFO); voices connect a bus only while it has a source (a connected silent bus costs +14% in Chrome).
- `synth.ts` handles voices: a note gets one voice node (`createVoiceNode`) into `preGain`, with the envelopes, the routes (`voiceRoutes`: the osc knobs of the oscillators on for it, the filter knobs in the range of its type while it is on, amount 0 left out; FX targets go to the fx model) and the filter of its note on. Playing notes, released ones too, follow Gain, Detune and Wave (`setTargetAtTime` ~10 ms, then set exactly so the param is constant again) and Oct (at once), the routes and the filter (messages, only to the notes whose own routes changed); unison, phases, on/off and the envelopes only new notes. A key released sets the gate to 0 (the release is in the processor). Poly counts the released voices until they end (or their release is over): above it the oldest released voice is stolen first, then the oldest held one. Legato: the notes pressed while another one is held start with the envelopes and the start of the phrase (they don't retrigger), each releases at its own key. `$fxNote` is the envelopes of the last note pressed (in legato of the phrase, released with its last key), the fx follow it. Every voice stays referenced until its processor posts `ended` (WebKit collects an AudioWorkletNode JS doesn't hold), then the node and its buses are disconnected. A voice whose processor throws ends the same way, alone: in `process()` the worklet catches it, gives its tables back to the store and posts `ended`, an error outside it (`onprocessorerror`) ends it on the main thread; the engine stays ready. Portamento also lives here.
- Envelopes (`synth/common/envelope/`): `envelope-curve.ts` (no imports, shared by the worklets, the main thread and the specs) is an envelope as a function of time, linear stages, the release from the level reached to 0 in its time; `envelope-block.ts` renders one per block in a worklet (a block within a flat stage is one value). The `env` model (`envelopes.ts`, snapshot `env: { e1, e2, e3 }`, stages 0..32 s, `ENVELOPE_DEFAULTS` in the schema) holds ENV 1–3, `$selected` (the tab, UI state) is not saved; the time knobs are `mode: 'pow'` (short times get most of the travel).
- Modulation: the `modulation` model (`modulation.ts`, snapshot `mod: { 'env2:osc1.wave': 0.5 }`, one route per source and knob) holds the routes, amount −1..1 a share of the knob's range in its scale (octaves for a log knob, `amountInUnits`); `modulation-targets.ts` is the registry of the assignable knobs (`osc1.gain|wave|detune`, `filter.cutoff|resonance|gain` in the range of the filter type, `<fx>.<param>` and `<fx>.mix` for every knob of `FX_REGISTRY`, not the switches). The ENV tabs (`envelope-tabs.tsx`) are dragged onto knobs with `startModDrag` (ui-kit, pointer events): a drop adds a route at +50%; `useKnobModulation(target)` gives a knob its `modTarget` and `modulations` (arcs, amount rings, the live dot of the last note's envelope while voices sound).
- FX modulation (`fx/effects/fx-modulation.ts`, `fx-automation.ts`): the fx model gives each effect `{ note: $fxNote, routes }` while it is in the chain, on and ready (null otherwise: nothing computed). The distortion and the reverb compute the moved knobs once per block in their worklets (`registerStereoProcessor`'s `modulate`: the modulator holds back the posted values of moved knobs, sets a value only when it changed); the delay's params and every slot's mix are automated (`scheduleRouted`: ramps between the envelope's corners, exponential for log knobs, 15 linear segments for clamped stages, the pan split at 0 and the equal power mix (no `setValueCurveAtTime`: an event inside a curve still running throws); Time without its tape glide; a delay mode change or an inactive delay leaves the automation of every feedback gain; the mix leaves its automation once when its routes go, its ticks without routes glide). The osc/fx switch (`TapeSwitch switchOnDrag`) flips when a dragged label stays on it 600 ms.
- `input-controller.ts` is the shared note-on/off bus. The on-screen piano, `keyboard-controller.ts` (QWERTY) and `midi-controller.ts` (WebMIDI) all feed into it.

### Snapshots

`app/plugins/snapshot.ts` creates one `searchParamsSnapshotPlugin`. Models that register it (`osc1`, `osc2`, `filter`, `env`, `mod`, `fx`, synth as `v`) expose their state as `{ [modelName]: { key: value } }`:
- `getSnapshot()` / `applySnapshot(obj)` read and apply the state at runtime (used by presets); `$snapshotChanges` emits on any change.
- Legacy URL params `<modelName>-<key>=<json>` are still applied on init.
- `applySnap` must handle falsy values (`!== undefined`, not `&&`), and missing keys mean defaults.
- When adding persisted state, extend the model's `modelToSnap`/`applySnap` **and** `presetDataSchema` in `libs/preset-schema` (unknown keys are stripped, so a missing schema field is silently not saved).
- Oscillator keys: `w` is the Wave position in frames (fractional), `ph`/`pr` Phase and Phase rand (0..1, default `DEFAULT_PHASE` 0.5 = 180° and 1). A legacy `r` (Phase rand as a start delay of 0..2 ms) is read only: without `pr` it becomes `pr = min(1, r / 0.002)` (`withLegacyPhase`, in the schema, `applySnap` calls it for legacy urls) and is not written; such a legacy preset or url without `ph` gets `LEGACY_PHASE` 0 (it played from the start of the wave), not the default.

### Presets (apps/waveform/src/app/presets, netlify/functions)

- `libs/preset-schema`: zod schema of preset data with ranges and defaults, `normalizePreset` (4 significant digits, sorted keys), `presetHash` (sha256 of normalized JSON, name excluded → dedup), profanity filter. Shared by the client and functions (functions import it by relative path, esbuild doesn't know tsconfig aliases).
- API (Netlify Functions v2, routed by `config.path`): `presets.mts` handles `/api/presets` (list/search with keyset cursors, save with Turnstile + 5/hour/IP), `/api/presets/top`, `/api/presets/:id` (GET, and PUT to overwrite), `/api/presets/:id/report`, `/api/presets/:id/opened`, `/api/presets/name-available?name=`; `usage.mts` stores listens and stays (each with a Turnstile token of its own). IPs are stored only as salted hashes.
- Scheduled: `recompute-scores.mts` (every 30 min) and `cleanup.mts` (daily, removes unqualified presets 90 days after they were saved, edited or opened by their author: `GREATEST(created_at, updated_at, author_opened_at)`; listeners not heard for 60 days; reports of hidden presets and those older than 180 days, so REPORT_HIDE_THRESHOLD counts the reports of half a year).
- Scores (`recompute-scores`, last 60 days): a listener is an `ip_hash` (`getIpHash` hashes `ipKey`: IPv4 as is, IPv6 by its /64, privacy addresses rotate), not a client id (clearing localStorage would make new ones). A listen is playing a chosen preset `USAGE_LISTEN_SECONDS` (10), a stay `USAGE_STAY_SECONDS` (60, both `libs/preset-schema`), both without switching to another one; presets skipped sooner are not counted (the top is stepped through with ◀ ▶ the most, their listens would weigh against it). The client sends each once a preset is opened (`POST /api/usage` `{ presetId, event: 'listen' | 'stay', turnstileToken }`), `usage.mts` keeps one `listens` row (migration 004) per preset and IP with the days of the last listen (`heard`) and stay (`stayed`, NULL if none), each renewed at most once a day; a stay sets `heard` too, so `stayed <= heard`. Listens on hidden presets and on the author's own ones (the preset's `ip_hash`) are not stored, the preset opened on start is not counted at all (its listeners didn't choose it). Each listen and stay weighs w, a 7-day half-life since its day. `score` = the share of listeners who stayed with a Bayesian prior: (Σ w stays + k·m) / (Σ w listens + k), m the site's share: Σ over all presets of their shares, each weighing min(Σ w listens, k), k = SCORE_PRIOR_LISTENERS (with every listen counted the top would make the average itself and its lower part would keep falling below it, out of the top); a share, not a count, so the top's extra traffic (start, ◀ ▶) gives it no extra score, and a preset with few listeners stays near m. `unique_users` = the listeners who stayed (shown in the lists). Only presets with MIN_UNIQUE_USERS of them get a score (and `qualified_at`). `cleanup` removes rows not heard for 60 days.
- Popular: `preset_scores.popular` with POPULAR_MIN_USERS listeners who stayed and a share not below m (m is a rounded numeric quotient, compared with a 1e-12 tolerance, so exactly the average counts): the bar doesn't grow with the audience, a preset found in the list gets in with listeners who stay. `/api/presets/top` (Popular tab, ◀ ▶, 50 presets) has every featured preset first (curated, `presets.featured`, whatever its score), the rest of it are such presets by score; the `popular` sort of the list orders all presets by score, whatever the threshold.
- Client: `presets` rxModel (current preset, dirty flag via hash comparison, ◀ ▶ list, `?preset=<id>` loading), `usePresetUsageTracker` (counts the seconds an opened preset is played: audio runs, tab is visible and a note is held or was played or released in the last 30 s; once a preset reaches `USAGE_LISTEN_SECONDS` / `USAGE_STAY_SECONDS` without switching it reports the listen / the stay, each once; the `auto` preset is not counted until it is chosen; another preset drops a listen or stay not reached, a hidden tab only pauses it), `UsageReporter` (rendered by `PresetSection`) sends them one at a time, each through a Turnstile widget of its own (`appearance: 'interaction-only'`, out of the layout, the script loads with the first event): the visitor never sees it, an event Cloudflare would ask to interact for, a failed check or no token in `CAPTCHA_TIMEOUT_MS` (30 s) is dropped.
- Start without `?preset=`: `openPopular` opens a random one of `/api/presets/top` as `auto` (unless something was loaded, saved or changed meanwhile: the state must still hash to `presetHash({})`). Random, not the first: no single preset is opened for every visitor; ▶ continues from it. An `auto` preset is not put in the url (after a reload it would open from the link as chosen). Init (the button between the name and ▶, `reset`) applies `normalizePreset({})` (not `applySnapshot({})`: some `applySnap` keep missing keys), clears the preset and the url. UI: `PresetPanel` in the header, `PresetBrowser` and `SaveDialog` antd modals. Cmd/Ctrl+S opens the save dialog.
- Editing: on create the server returns a secret `editToken` (only its sha256 is stored in `presets.edit_token_hash`); the client keeps tokens in `localStorage.presetEditTokens`. `PUT /api/presets/:id` with the token overwrites sound and name (no Turnstile, 1 update per 5 s, 409 if the sound is another preset's). Presets created before migration 002 have no token and can't be edited. Opening an own preset (`applyPreset` with a token in `localStorage`, once a session) posts the token to `POST /api/presets/:id/opened`, which sets `presets.author_opened_at` (migration 005, at most once a day, a wrong token changes nothing): the author keeps it from the cleanup.
- Names are unique case-insensitively with collapsed whitespace (`presetNameSchema` normalizes, `presets_name_key` is a unique index on `lower(name)`, migration 003). Hidden presets keep their names. The save dialog checks availability while typing; saving the same sound under a taken name still returns the existing preset (dedup by hash comes first).
- QWERTY notes are ignored while focus is in a text field (`keyboard-controller.ts`).

### Wavetables

- The Netlify functions (`netlify/functions/get-wavetables-list.ts`, `get-wavetable.ts`) list the wavetable files in an S3 bucket as a folder tree and serve them. The client fetches the list with react-query (`synth/oscillator/hooks/use-wavetables.ts`). The table itself is loaded by the oscillator model from `$waveTablePath` (last path element = S3 key, `synth/services/wavetable.ts`, cached per session, 2 retries), so it follows presets whatever screen is shown; `WaveSelector` only shows `$waveTableLoading`.
- The files are wavetables in mono 32-bit float WAV (44.1 kHz, 2048-sample waves, 256 at most: the manual editor adds no wave to a table of 256). `synth/services/wav.ts` reads their samples from the bytes; not `decodeAudioData`, which resamples to the context rate (at 48 kHz a 2048-sample slice is 1.09 cycles and a table has ~278 waves instead of 256).
- The wavetable editor (`synth/wave-table-editor/`) also builds tables from manual drawing or from an uploaded audio file. `synth/services/audio-file.ts` reads that file at its own rate, never at the context's: a WAV through `wav.ts`, other formats decoded by an `OfflineAudioContext` at 44.1 kHz (their rate is unknown before decoding).

### Libs

Libs are imported through the path aliases in `tsconfig.base.json`: `@waveform/math`, `@waveform/rxjs-react`, `@waveform/ui-kit` and `@waveform/preset-schema`.

- `math`: number, vector and typed-array helpers, plus FFT-based wave utilities.
- `ui-kit`: styled-components UI widgets (charts, knobs/handles, piano, analysers, ADSR) and `theme`/`GlobalStyle`. `Handle` and `Fader` take `mode` linear, log or pow (`valueScale`), `modulations` (arcs or bars of the colors of their sources, `AmountRing`s: drag to change, double click or long press to remove) and `modTarget` (the drop target of `startModDrag`, none while disabled). The app also uses antd 5, themed in `app/index.tsx`.
