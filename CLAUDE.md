# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Chisper is an experimental browser wavetable synth (TypeScript + Web Audio API, React 19). An Nx 24 monorepo: the synth (`apps/chisper`), its promo pages (`apps/site`, Astro), four libs (`libs/math`, `libs/rxjs-react`, `libs/ui-kit`, `libs/preset-schema`), Netlify functions in `netlify/`, a Postgres database for presets, the DSP of the worklets in Rust (`dsp/`). Deployed to Netlify at chisper.qvantor.org (named Waveform before: `waveform.qvantor.org` is a domain alias that `netlify.toml` redirects there, its links of presets too).

Tooling:

- Nx 24, inferred tasks only (`plugins` of `nx.json`): `@nx/webpack/plugin` build and serve from `apps/chisper/webpack.config.js` (plain webpack: `NxAppWebpackPlugin` + `NxReactWebpackPlugin`), `@nx/jest/plugin` test from each `jest.config.ts`, `@nx/eslint/plugin` lint from each `eslint.config.mjs`; `project.json` only overrides (the test inputs of `chisper`).
- TypeScript 6 (`moduleResolution: bundler`, no `baseUrl`, `lib` es2022), ESLint 9 flat config, Prettier 3 (`trailingComma: es5`; the format-only commit is in `.git-blame-ignore-revs`).
- Jest 30 on jsdom 26: computed colors are `rgb(…)` (`cssColor` of `@chisper/ui-kit/test-utils`), `window.location` can't be replaced.
- styled-components 6 (`import { styled }`): style props only transient (`$size`), v6 passes the others to the DOM; `StyleSheetManager enableVendorPrefixes` at the root keeps the prefixes v5 added.
- antd 6, react-query 5, zod 4: an object default is `.prefault` (`.default` doesn't parse its value in v4, the preset hashes would change; `preset-hash-goldens.spec.ts` holds them).
- Not the latest on purpose: TypeScript 7 (no JS API: typescript-eslint, ts-jest and Nx need TS < 7), ESLint 10 (eslint-plugin-react of the Nx React preset breaks on it), Babel 8 (Nx runs Babel 7), `@types/node` 26 (Node 24 of `.nvmrc`), webpack-dev-server 6 (`@nx/webpack` takes 5).

## Architecture

### State: `rxModel` (libs/rxjs-react)

All app state and audio logic live in RxJS "models", not React state. The pattern:

```ts
const model = (deps) =>
  rxModel((initial) => ({ $foo: new PrimitiveBS(0), audioNode, ... }))  // state: BehaviorSubjects + Web Audio nodes
    .actions((model) => ({ setFoo: (v) => model.$foo.next(v) }))
    .subscriptions((model, actions) => [ ...rx subscriptions wiring state to audio... ])
    .plugins(urlSnapshotPlugin({ modelToSnap, applySnap }))
    .destroy((model) => { ... });

export const { ModelProvider: FooProvider, useModel: useFoo } = rxModelReact('fooModel', model);
```

- Each builder call returns a new immutable factory; `init` runs actions, subscriptions, and plugin `onInit`; unmount runs `destroy`, unsubscribes, and plugin `onStop`.
- `rxModelReact` wraps a model in a React context. `<FooProvider initial={...} {...deps}>` takes the `initial` value plus dependency props (other models' `[model, actions]` tuples); `useFoo()` returns `[model, actions]`.
- Components read observables via `useBehaviorSubject($x)` / `useObservable`. BehaviorSubject helpers: `PrimitiveBS`, `ArrayBS`, `ObjectBS`. Observable names use a `$` prefix.
- Dependency injection is done through provider nesting, so provider order matters. The tree in `apps/chisper/src/app/synth/index.tsx` defines it: InputController → SynthCore → Transport (the tempo and the beats) → Envelopes → Lfo (the voices node of the synth core runs them) → Modulation → Oscillator1/2 → MidiController (a MIDI Clock leads the transport) → Filter → Synth (the filter in its voices) → Fx (follows the synth's last note and the LFOs) → SoundSwitch (a preset switch silences them) → KeyboardController → Presets.

### Audio graph (apps/chisper/src/app/synth/common/modules)

- `synth-core.ts` owns the single `AudioContext` and the wavetable engine (`wavetables`, `createWavetableEngine`): `voices node → preGain → fxIn → [fx chain] → fxOut → masterGain → masterLimiter → destination` (every note plays in the voices node, the filter is in each voice). `mute(seconds)`/`unmute()` (the sound switch) fade `fxOut.gain` out and step it back to 1, nothing else automates it; the limiter's `clear` (`fx_clear`) forgets the gain reduction of the sound before. `$masterGain` is linear; the Master knob (`master-handle.tsx`) shows it in dB from −40 (silence) to +12 (above 0 dB it drives the limiter).
- The header analysers tap `output` (after the limiter): `FqAnalyser` and `VolumeAnalyser` of ui-kit draw on screen frames (`meterLoop` of `meter-loop.ts` on the `onFrame` ticker, at most every `MIN_FRAME_MS`) while a voice sounds (`$voicesCount` > 0) and after the last one until they have drawn nothing for `quietMs` (`QUIET_MS` 1.5 s, or the longest gap between two echoes of the delay + 0.5 s: `$echoGap` of the fx model, up to 4 s in BPM), then they sleep: no frame, no commit of their canvases (a blank frame after a blank one isn't drawn). The spectrum draws a column per pixel of the axis or more (bins narrower than a pixel merged, as tall as the loudest); the meter reads a window of 4096 (`FFT_SIZE` of `meter.ts`: only what the main thread copies out; Chromium's analyser writes each quantum into a ring of its own at any fftSize).
- The latency of the output (`synth/common/latency/`): the `latencyHint` of the context, chosen at its creation (`resolveLatency` of `latency.ts`), so a change reloads the page (`reloadPage`: the tab keeps the sound and the MIDI input). Only desktop Chromium takes the hint (`canChooseLatency`: the brands of `navigator.userAgentData`, not `mobile`; Safari and Firefox ignore it and get no choice): low is `0` (128 frames: `baseLatency` 2.67 ms + `outputLatency` 8 ms at 48 kHz on macOS), normal `'interactive'` (256 frames; a hint between them rounds up to 256). The mode (localStorage `latencyMode`: auto, low, normal; where the storage keeps nothing, `canKeepLatency`, it is normal with no choice) is chosen under the Settings key, right of Midi (`settings/settings-button.tsx`; the page reloads, so its select has no ◀ ▶: `arrows` of the ui-kit `Select`). Auto starts low and plays normal once it learnt it (localStorage `latencyAuto`; auto chosen again forgets it), only where the browser counts dropouts (`canCountDropouts` of `dropouts.ts`: `AudioPlaybackStats` with `underrunEvents`, the interface, and `playbackStats` on `AudioContext.prototype`; Chromium before 146 has none: auto is normal there, a low chosen by hand stays and its note asks to choose normal if the sound crackles). At low the synth core polls `playbackStats.underrunEvents` once a second (`$dropouts`, shown in the settings): `DROPOUT_SECONDS` (3) seconds with new ones within `DROPOUT_WINDOW` (60 s of `performance.now`; a hidden page polls once a minute) and auto keeps normal from the next start on (those while a preset switch silences the output, `$muted`, and `REPORT_LAG` 2 s after are shown, not counted); `$dropoutWarning` shows a toast that offers normal now (`switchToNormalLatency`: a low chosen by hand becomes normal; once, `dismissDropoutWarning`). The clocks of the context don't show a dropout (`currentTime`, `getOutputTimestamp`), and Chromium 133 grows its FIFO after one (its PushPullFIFO earmark) without telling `outputLatency`: a lateness worked out in a worklet (only `Date.now()` there) is no signal.
- The master limiter (`synth/common/limiter/`) is the last stage, after the master volume. Its core (`dsp/limiter`, `limiter-wasm.ts`, the ceiling in `limiter-params.ts`; `limiter-dsp.spec.ts`) is a stereo linked brickwall at −0.5 dBTP with a 4× true peak detector (`dsp-core/src/true_peak.rs`, polyphase Kaiser sinc whose phase 0 is the input itself), 2 ms lookahead, the needed gain held for 20 ms (it never moves inside a bass wave), a fast (50 ms) and a slow (0.5 s) release envelope (short peaks let go fast, dense parts slowly, no pumping between their notes; once the sound has needed less than the slow one for 250 ms it lets go at the fast rate, down to what the sound still needs) and two moving averages over the lookahead (S-shaped attack). The detector runs both channels in the lanes of f64x2 (`StereoTruePeak`: a quiet channel its sample alone), skips the interpolation while the last 32 samples of a channel are below `TRUE_PEAK_BOUND` (−8.6 dBFS: no point between them can reach the ceiling) and sums its 3 phases in one pass over the history. Once it has let go and its input has been +0 on both sides (the bits: a −0 or a NaN is rendered) for its latency it is `at_rest`: it skips a block of +0 (its output +0) and moves its rings on as rendering it would (`skip`: the state of a limiter that rendered it, to the bit, the crate spec holds it; `fx_idle`, the `idle` of the facade, for the specs). No sample goes over the ceiling, the true peak of band-limited sound stays under 0 dBFS (the 4× grid reads at most cos(π·f/4) low); below the ceiling, once released, the sound passes bit for bit, delayed by `latency` (2.3 ms at 48 kHz). After a chord through the native delay its feedback keeps the input of the limiter above 0 for 20–40 s. `limiter.worklet.ts` registers the processor, `master-limiter.ts` loads it with `createWorkletFx`; until it is ready (loading, or the module or its processor failed) the master is silent (no fallback: the oscillators need AudioWorklet and wasm SIMD too); a failed one shows a toast on every screen (`LimiterStatus`, `synth/synth/components/`) whose Retry loads it again, with the oscillators if they failed too (`retryAudio` of the synth core).
- The `fx` model (`synth/fx/`) wires the FX rack between `fxIn` and `fxOut`. Effects are defined in `FX_REGISTRY` (`fx/effects/`, params and ranges from `FX_PARAMS` of `libs/preset-schema`); adding an effect type means a registry entry plus its preset schema. `createFxSlot` wraps each one: `mix` is a crossfade (`mixGains`: 0 only dry, 1 only wet; equal power for delay and reverb, both at −3 dB at 0.5; linear for a core with `linearMix`, the distortion: its wet signal is the dry one reshaped and in time with it, equal power would be 3 dB louder in between); the default mix is per type (`FX_MIX_PARAMS`: the distortion all wet, delay and reverb 0.3); bypass passes only the dry signal at full level; a core with `latency` (the distortion) gets its dry signal delayed as much (`dryDelay`), so the timing never jumps and the mix doesn't comb filter. The chain is the added effects in `$order`. `clear()` (the sound switch, after the next preset is applied) makes every effect, in the chain or not, forget its tail at once (`FxCore.clear`) and sets the gains of its slot (send, dry, wet) at its knobs at once (a mix its routes move follows them): the worklets post `{ clear }` (`fx_clear` of their cores: emptied and idle as once drained, the next sound starts at the params as they are then, no glide from those before), the delay makes its lines, bandpasses and pan offsets again (a DelayNode can't be emptied: fed silence it plays its last second) at the values of its knobs at once (`instantly` of `createFxParams`: from the defaults of a node Time would chirp). `FX_TYPES` is the default chain order (distortion, delay, reverb); `normalizeFxOrder` puts a type missing from a saved order at its default place, before the first effect that follows it in `FX_TYPES`.
- The delay has BPM/MS (`sync`, `trip`, `dot`: BPM over T and D on one plate beside Time, `stack` of `SwitchKeys`, as large as its ring; on the keys view of a phone at 780 px the delay is on one line; faded with the delay off; params with `options`, so no route targets): in BPM Time is `div` (`delayDivisions`, `delayStepsOf`: the same array for the same switches) at the tempo (`setTempo` of `FxCore`, the fx model passes `$tempo`); BPM switched on takes the division nearest to Time, MS the seconds of the division within the range of Time, TRIP or DOT switched off the straight division (`paramChange` of `FxDefinition`, `delayParamChange`: a change of the user through `setParam` of the fx model, not a preset). Its lines are 4 s long (`DELAY_LINE_MAX`: a bar at 60 BPM; longer plays 4 s), a new tempo glides there with `TIME_GLIDE`; the fx-mod line of Time takes the seconds of the division as its base, the routes to Time are bounded by its divisions at the tempo (`delayTimeBounds`).
- The reverb runs in an AudioWorklet: its core (`dsp/reverb`, `reverb-wasm.ts`, its params in `reverb-params.ts`; `reverb-dsp.spec.ts`, with impulse responses; the tables of its lines in `reverb-decay.ts` and `reverb-era.ts`, the chart draws them) is a 16-line FDN: its lines in pairs in the lanes of f64x2 (line 2p, which goes left, in the low lane, 2p + 1 in the high one; each lane the operations of its line, the sums in their order), the input stage, the predelay and the diffusers of both channels in the lanes too, the hermite reads by integer indexes (ToInt32 once). `reverb.worklet.ts` registers the processor, `reverb.ts` creates the `AudioWorkletNode` once `loadWorklet` has added the module and posts param changes to it.
- Worklet modules register their processor with `registerStereoProcessor` (`fx/effects/stereo-processor.ts`: the AudioWorkletGlobalScope declarations, a mono input feeds both sides, a disconnected one is silence, `stop` ends it), their nodes are created with `STEREO_WORKLET_OPTIONS`. A worklet module must not import `@chisper/ui-kit`, `@chisper/preset-schema` (zod) or anything touching `window`/`document`. In a hot loop of JS (a worklet, the probe of the perf build) don't chain calls per sample that return doubles through closures or polymorphic sites: V8 boxes every such result (garbage and CPU on the audio thread); run each stage over the block in typed arrays.
- The distortion runs in an AudioWorklet too (`distortion.ts`, `distortion.worklet.ts`): its core (`dsp/distortion`, `distortion-wasm.ts`, its params in `distortion-params.ts`; `distortion-dsp.spec.ts`, aliasing included) drives the input (0 to 12 dB: more folds back audibly on high notes at 4×) into the curve of the mode, oversampled 4× (the hard clip 8×) (`dsp-core/src/stereo.rs`: polyphase windowed sincs, `fir.sincPhase` of `libs/math`, linear phase, `DISTORTION_LATENCY` = 32 samples; the decimator is the one of the true peak detector, cut at the nyquist; the interpolator is cut at 0.9 × the nyquist, flat up to 0.4·fs, so its phase 0 is not the input itself: cut at the nyquist it passed half of the images of the partials just below it, which the curve mixed into inharmonic tones), × its makeup gain (`MAKEUP_TABLES` of `consts.rs`, worked out as `test-utils/distortion-makeup.ts` does: per mode over the drive, keeping the RMS of a reference sine of `REFERENCE_PEAK` 0.5; 1:1 with the drive while the reference is unclipped, then it levels off towards −9 dB, −7.1 dB soft and −8 dB hard at 12: the curve compresses), then the tone lowpass (faded out at the top of its range, `TONE_OPEN`: the wet keeps the phase of the dry), the level (a trim on top of the makeup) and a DC blocker (one pole at 5 Hz, `DC_CUTOFF`: the curves are odd, but an asymmetric wave, a narrow pulse, gets DC from them; the tests of the gains undo it, `unblock`). Drive, makeup, level, tone and a new mode (a crossfade of the curves, each with its makeup; the mode changed back during a fade turns it around where it is) glide. The gains go on the oversampled points, before the decimator. The chart shows the curve of the mode at the drive within ±1, without makeup and level. The modes are `DISTORTION_MODES` (`distortion-modes.ts`: soft clip = tanh, hard clip): `mode` is an index into it, so new modes are appended and `FX_PARAMS.distortion.mode.max` raised; a curve is odd, within ±1 and has the slope 1 at 0 (bitcrush would need a state of its own). It has no loops: `setActive` does nothing; once its input has been silent longer than the oversampler rings only the tails of the tone and the DC blocker are rendered (~0.7 s after a DC-heavy sound), then it clears its state and skips the blocks. Each stage runs over the block (`up`/`down` and `shape_block`, both channels in the lanes of f64x2), the same to the bit as sample by sample. The hard clip has a chain of its own (`StereoOversampler8`, `UP8_PHASES`/`DOWN8_PHASES` of `consts.rs`: 32 taps per phase at the input rate, so the latency stays 32 samples; 7 kHz at 12 dB aliases at −62.8 dB, 10 kHz −56.7), the soft clip stays on the 4× chain; a fade between modes on two chains runs both, their outputs added at the input rate; a chain that starts takes the input history of the other (its interpolator as if it had run, its decimator at 0), one that stops flushes its decimator with points of 0 for 33 samples, so the output is the one of both chains running all the time (the crate spec checks it).
- A worklet effect builds on `createWorkletFx` (`fx/effects/worklet-fx.ts`: loading, input → node → output, `$status`, `retry`; `destroy` posts `stop` to the processor, so does a failure: a processor that threw still takes it, its core is freed; a stopped processor takes no message). Without AudioWorklet (http on a LAN IP, old Safari) or when its module fails, the app still works: the fx model keeps the effect out of the chain (it stays `added` in the snapshot), and the Effects list shows why under its name. An unsupported effect can't be added, an added one that can't be used can still be removed, a failed one loads again on Retry or when it is added. Until an effect is `ready` (also while it loads) its slot passes only the dry signal and is inactive.

### The oscillators and the voices (synth/common/wavetable)

- No native fallback: without AudioWorklet, Worker or MessageChannel the synth doesn't play and each oscillator shows why over its wave (`OscillatorStatus`; Retry for a failed module: `retryAudio`, the limiter too if it failed), else why its table doesn't play (refused by the store or failed in the worker: the previous one plays, Retry sends it again).
- `wavetable-engine.ts` (one per context, in the synth core): `$status` loading/ready/unsupported/failed (module, worker, store or voices node) and `retry` (as `createWorkletFx`); the store node (`STORE_PROCESSOR`, 0 inputs, 1 output never connected: 0/0 isn't allowed), the voices node (`VOICES_PROCESSOR`, into `preGain`), the worker (`wavetable.worker.ts` → `wavetable-builder.ts`) and a MessageChannel between worker and store. `setTable(id, frames)` transfers copies of the frames to the worker, which builds the levels (`wavetable-mipmap.ts`; a newer version replaces a waiting one) for the store (`createTableStoreWasm`, one per AudioWorkletGlobalScope, refcounted versions in the core's memory): it answers `{stored, version}`, `{refused, version}` (no memory) and `{freedBytes}`. The engine listens to both in every build (ports started: nothing piles up): `$tables` gives each table's latest version `sending`, `stored`, `refused` or `failed` (the worker's `{failed, version, reason}`: a build that threw, an allocation on a phone; only an error of the worker itself fails the engine); `retryTable(id)` sends it again; a refused version is resent once when the store frees memory (refused again, it waits for Retry); the oscillator model mirrors it (`$tableState`, `retryTable`). Tables are kept and resent after a retry; versions only grow.
- `createVoice(options, values)` makes a note's voice in the voices node, null until ready (a note played meanwhile isn't played later): a `VoiceHandle` with its id and `params`, per param the AudioParam calls the synth makes (`ParamAutomation`: setValueAtTime, setTargetAtTime, exponentialRampToValueAtTime, cancelScheduledValues), each an event of the node (the value in f32 as an AudioParam keeps it; none after the voice ended); `setRoutes(ids, routes)`, `setFilter(ids, filter)`: one event for the voices that get the same. A task's events go in one message (`{ events }`, sent by a microtask; `flush()` in specs) in creation order. After a block with any the node posts `{ started: [[id, started, scheduled]], ended: [id] }` (`onStarted`, `onEnded` of the handle). An error of the voices node (`onprocessorerror`) fails the engine: it is stopped (`{ stop: true }`: the voices give their tables back), every voice ends (the synth lets their keys go), Retry makes it again; destroy stops it silently.
- Under `__PERF__` (perf build, Jest): `pending()` (tables whose latest version isn't stored yet) and `stats()`: the store's (`{stats: true}`: versions and bytes held, live voices and their unison, samples from mix tables or direct, mix builds and refusals, mix tables and their bytes, counted by the core's shared, `createVoiceSharedWasm`), the worker's (pending tables, freed-buffer pool, build ms), the node's voices and their timeline events (`scopeVoices`, `events`). A voice with `trace` in its options is told started (the frames) once; the synth traces voices only while `$voiceStarts` is observed. Every voice that started late is told too, in production as well (the fx and Poly follow it), and every mono voice (`mono` of its options).
- Levels (`wavetable-mipmap.ts`; the layout without imports in `wavetable-levels.ts`, `createLevels`, so the worklet bundles no FFT): a third of an octave apart on the grid of Chrome's PeriodicWave (`levelBase`: harmonics up to 1024·2^(−r/3), at most the frame's 1023, then a silent level of 1 sample), each 32 samples per cycle of its highest harmonic, 512..4096 (`levelLength`), 1 guard sample before a frame and 2 after; DC and the nyquist bin dropped, at the file's volume (not normalized as createPeriodicWave does), phases kept; frames of 16..2048 samples, `MAX_FRAMES` 256 (≈ 63.6 MiB). 256 frames build in ~150 ms (Firefox ~300).
- The voice: core `dsp/wavetable-osc` (`voice.rs`, through `wavetable-osc-wasm.ts`; options and messages in `voice-options.ts`; `wavetable-osc.worklet.ts` registers the voices processor and the store; `wavetable-osc-dsp.spec.ts`). Every note is a voice of the voices node (`VOICES_PROCESSOR`, one per context; `voices-processor.ts` on `createVoiceScopeWasm`, `scope.rs`): both oscillators (null in `options.osc`: off for the note) with their unison voices, rendered by `Voice::process` in creation order and summed in f32 in that order into one stereo output.
- A voice arrives as an `on` event (options + param values at note on), its params as automation events, each a timeline of the core (`timeline.rs`) with AudioParam semantics (setValueAtTime, setTargetAtTime, exponentialRampToValueAtTime, linearRampToValueAtTime for bench-osc's LFOs only, cancelScheduledValues; the Web Audio formulas in f64 from f32 values, each clamped to the range of its descriptor, `VOICE_PARAMETERS`). An event acts from the first frame not before its time; a late one (messages arrive between quanta: a release or a knob may be a quantum later than synchronous automation) from the block it arrives in; one of the same kind at the same time replaces the one there (as Chromium); events of an ended voice are nothing; those the 0.5 s history passed are forgotten (their value kept). A block without a change is one value; a param without events is its value without a call (`render` of `timeline.rs`). After a glide or a knob turn a voice may differ from a browser's AudioParam in the last bits of f32 (inaudible).
- Params (`wavetable-osc-params.ts`): `frequency` (portamento glides it); `gate` (1 held; `RELEASE_GATE` + h: released h seconds after the start; 0: released at that sample; below 0: a stolen voice fades out in 20 ms, a raised cosine; held at another value (1 and 1.5 alternate) or held again after a release, the envelopes start again at that sample (mono), each from its level there: `retrigger` of `envelope.rs`, earlier samples keep their envelope, a release is off; not on a stolen voice nor past its end; exact to the sample); per oscillator `position` (frame k of N at k/(N−1)), `detune` (cents: 1200·octave), `spread` (cents over the unison), `gain`, `blend`. Options (read at note on): table id, unison 1..8 (one voice at spread 0 unless a route raises the spread; a stack or a position spread keep them all), `phase`/`phaseRand` (shares of a period), `unisonShape`, `envelopes` (ENV 1–3) and `envStart` (legato: the start of the phrase), `routes`, `filter`, `velocity`.
- The volume is ENV 1 (`envelope.rs`, exact to the sample, the release from the level reached); the voice ends where ENV 1 is back at 0, reported in that block. A voice processed after its start (its note on came a device buffer late) starts its envelopes at its first sample (`startAt`: the attack isn't skipped). A legato note starts them where the first voice of its phrase did (`join_phrase`/`phrase_frame` of `shared.rs`: phrases by their scheduled frame, kept while a voice of them plays; a first voice not yet started starts in the same block). The release starts h after the voice's first sample (or its last start again), not before the gate is seen, at most `RELEASE_LEAD` after it.
- Routes (`modulation.rs`) replace the params they move (position, spread, gain, blend per oscillator; the filter knobs): base + Σ amount × level (log: base × 2^Σ), clamped to the knob's range. Semi and Fine are two params of base 0 (`pitch1`, `fine1`), each clamped to its routes' bounds (the knob's range from its value), added with the bend to the detune only where it is read (the first sample and the pitch points: `Detune` of `voice.rs`). While every envelope a param follows is on a flat stage and no amount glides, the param is one value (the voice stays on its mix table); an envelope no route reads isn't rendered; a changed route glides in 10 ms (a `routes` event; its polarity too: the ½ a bipolar route subtracts glides). A moved param isn't copied: its values go into an override the voice reads instead (`Osc.moved`, `moved` of the filter, through each target's `ParamAccess`: by computed names V8's accesses go megamorphic).
- Source 3 is always VELO (`VELO` of `modulation.rs`; a route of an envelope the voice lacks moves nothing): the velocity (`velocity.rs`; options `velocity`: a level and an amp, read at note on; none: no VELO, amp 1) is one value, so its routes keep the voice on its mix table. The amp multiplies the output with ENV 1 in its pass, before the fade of a stolen voice (`Volume`: one rounding to f32; at 1 nothing changes); a `velocity` event (mono: a note takes the voice over) glides both in 10 ms.
- The filter (`filter.rs`; a `filter` event, null: off; both channels in the lanes of f64x2) after the oscillators, before ENV 1: coefficients of `coefficientsInto` (`@chisper/math/biquad`, an alias that keeps the FFT out of the bundle) every 32 samples, only when a value changed; knobs glide ~10 ms (another type takes them at once, its state goes on: a bandpass Q is linear, a lowpass Q in dB).
- Unison (`unison.json`): voice j of n is detuned by spread·(j/(n−1) − ½) (linear mode); the middle one of an odd count plays both channels, the others alternate right/left from the lowest (a voice and its mirror on opposite sides); levels per count against one voice (`UNISON_LEVELS` of `voice.rs`: a voice of 2 −1.9 dB, of 3..8 a side voice at blend 0 +0.9…−0.4 dB), the middle one of an odd count ≥ 3 at `CENTRE_PAN` (−8.02 dB) per channel.
- Blend (`blend` per oscillator, the Blend knob, a route target; `blend_gains` of `voice.rs`, `blend.json` within 0.04 dB): the centre voices (the middle one of an odd count, the middle two of an even one) at 1 − 0.5549·b², the others at 0.04453 + 1.2887·b² − 0.74024·b⁴, never silent; a unison of 2 is all centre. A still blend sets the voice gains when it changes (`set_blend`, folded into the loops). One that moves within a block renders the voices at 1 into the oscillator's channels (the middle two of an even count apart in the mid channels of the scratch, `a_mid_*`, `b_mid_*`; the middle one of an odd count in the centre channel), then `mix_blend` gives each group its gain at the modulation points (every 32 samples from the span start, then its last sample), linear between (within 2.2% of per-sample gains for a sweep of the range in 5 ms: `BETWEEN_POINTS`), then the width; the voices stay on their mix tables. `unison-levels.ts` of the app has the same levels for the voices it draws.
- Unison shape (`UnisonShape` of `voice-options.ts`, `shape_unison`; the defaults `UNISON_SHAPE` are a plain unison): `width` (1: hard left/right; below it the oscillator renders into its own channels and each side channel takes the other × sin and itself × cos of (1 − w)·π/4: equal power, mono at 0; the centre stays; `mix_osc` over slices); `stack` (`UNISON_STACKS`: 12 (1x, 2x, 3x), 12+7 (1x, 2x, 3x), Center−12/−24; voice j of n at d = j − ⌊n/2⌋; the centre (d 0, and −1 of an even count) moves only by the Center stacks, a single voice too; the others by a = |d|: 12 (kx) up 12·(a mod (k + 1)), 12+7 (kx) up 7 at a mod 4 = 2 plus 12 ((k − 1)x); in an even count a voice and its mirror move apart); `detune` (`UNISON_DETUNES` over x = 2j/(n − 1) − 1: linear x, super tan(x)/tan(1), exp x·|x|, inv sin(x·π/2); `random`: random spread shares sorted from the lowest, drawn by the facade after the 8 phases of the oscillator); `positionSpread` (−1..1: voice v, in detune order from the lowest, at position + `SPREAD_OFFSETS[v]` × spread × table, 0, −½, +¼, −¼, +⅛, −⅛, +1/16, −1/16, whatever the count, mode or stack, within the table, moving positions too: the lowest (right) stays, at +50% the next (left) plays a quarter of the table below; a mix per voice). All of it is checked against the renders (`unison-modes`, `spread.json`). The oscillator model holds it (`$unisonShape`, `setUnisonShape`: no knobs, not in snapshot or schema yet; the perf hook reaches it).
- Phases: every voice starts at `phase` plus a random share up to `phaseRand` (0: all in phase, their beats sweep the spectrum, a louder onset; 1: any phase, steady, the power of one voice); the lowest voice of both oscillators starts at one share of the note (the first draw of the first oscillator on; osc 2's first draw isn't read), the others at their own (`phases.json`); at `phaseRand` > 0 voices start at once (the click of a fast attack is part of the sound); a legato note fades in (it would step to the level of the phrase).
- Pitch → level on Chrome's grid (x = `1 + 3·log2(base·f/nyquist)`): level floor(x) alone, every harmonic below the nyquist, its top from nyquist·2^(−1/3) (17.5–22 kHz at 44.1 kHz), crossfaded into the next only over the top fifth of its third of an octave (`LEVEL_BAND` 0.2; `level_x` of `voice.rs`, a whole number most of the way). Aliasing bounds −70 dB, spurs −80 (`band limit` of `wavetable-osc-dsp.spec`); wider bands sound the same below 12 kHz and cost more; a level is read at its own length.
- Frames: a position plays one frame, not a mix of two (`frames.json`): share v of M frames plays frame ceil(v·M) − 1. A frame change fades in (`FrameFade`, `frame-fades.json`): each unison voice decides at the points of a block (every 32 samples while pitch or position moves, else at the block start) and fades from its frame into the point's linearly over its own period there (detune, spread, stack), at most `FRAME_FADE` 5 ms, its length fixed at the start; a change meanwhile waits for the first point after the fade (frames between are skipped); a new voice starts on its frame, a mono voice taken over keeps its own; samples rendering nothing (above the nyquist, a silent table) still count; on a silent table the frame follows the position; each table version keeps a frame state per voice (`Osc.frame_fades`, a slot per version): the previous version's when it has as many frames, else each voice starts on its frame. A fading voice plays both frames directly, no mix. A moving pitch or position is worked out every 32 samples and interpolated.
- Mixes (levels are read linearly): a pitch on the flat of its level reads that level's frame alone (one table, as a mix is, from the first block, no build: a `MixKey` of w 0, `source`); one in a crossfade, while pitch, position and table stay (from its second block), sums frame × 2 levels into a mix table of its level's length (the next level as long or half: 6-point Lagrange ×2), built under a per-block budget across the scope (`MIX_BUDGET_WASM`, 360k multiply-adds); buffers are pooled, each as long as the longest level (`MAX_LEVEL_LENGTH` 4096: any takes any mix); a voice keeps its mix while it reads a level alone (a returning pitch takes it again) and gives it back when it or its version ends.
- A moving pitch (glide, bend, a route of Semi or Fine; the position constant, no version coming) plays a mix too (`Mixing::Reach`): the one it has while its pitch at every point of the block stays within `MIX_REACH` of the pitch it was built at (a quarter of a level in x: 20 cents over a crossfade; `MixKey`: frame, level, weight of the next), below where its richest level reaches the nyquist (`holds`), so every harmonic is within 0.25 of its direct gain; else a kept mix whose reach holds the pitch; else a level alone within half a level (`LEVEL_REACH` 0.5: its flat and the halves of the adjacent crossfades; the harmonics one level has and the other lacks, 0.76..1 × nyquist, within 0.5 of their direct gain; no build; a still pitch only on the flat, in a crossfade it builds its own mix the next block). Where neither holds (a block across the middle of a crossfade) a mix is built at the middle of the reach band the pitch holds (`PitchBand`, x / `LEVEL_BAND`, every block since it moved within `MIX_BAND`), once the pitch has held it as long as the build costs played directly (`MIX_PAYBACK`, 0.3 samples per multiply-add) and a glide as fast would stay as long again: fast glides (a kick, an octave in 100 ms) and wide vibratos (±200 cents at 3–8 Hz) build none (levels alone, directly across the middles of crossfades), a slow vibrato builds at its turns. A steady block takes back a mix of its pitch it still has (a bend that came back); one the budget can't build yet plays the mix whose reach holds the pitch meanwhile.
- A change of the table a voice reads (mix or level alone, either way; the first block takes its own at once) glides the levels it reads (`SourceFade`: x of the table or the pitch, linear over the voice's period from a block start, at most `FRAME_FADE` and no slower than the moving pitch moves the levels itself, at the block points, played directly, the mix after it): a mix is up to `MIX_REACH` off the gains of a level's top third of an octave (0.63..1 × nyquist), which would step. At once: a mix of the pitch the voice played directly (bit for bit), and a pitch that stepped past the reach (of a level alone or the middle of a glide half a level; `SOURCE_SLACK` 0.01: a pitch's move in a sample). A voice leaves a table as far before the top of its reach as the pitch rises during a glide, so no glide reads a level richer than the pitch past where it reaches the nyquist (`x_at` clamps to the floor of the pitch's x). While the pitch moves a unison voice's step is the oscillator's × its spread-and-stack factor: one pow per point (per voice when the spread moves in the block).
- A param is constant when its array has one value or all equal (silent inputs give 128; Firefox gives 128 equal values without automation): routes on a flat stage, the gate and the pitch take it as one value. A new table version is crossfaded in over 10 ms. Block buffers are shared across the scope's voices; Float32 channel buffers are copied once into the outputs (many writes to the outputs were slow in WebKit).

### The synth (synth/common/modules)

- `oscillator.ts` holds the frames (`$waveTable`); `$morph` (the table plays expanded to 256 frames by crossfades: its file has a morph mark or the audio-file editor made it; `setWaveTable(frames, morph)`; the engine sends it with the frames, the worker expands them: `wavetable-frames.ts`); `$frames` (the frames played: 256 expanded, else the table's); the Wave position `$position` (in played frames, 0..$frames−1; the knob steps whole frames, a fractional one from a preset or a route plays the frame of its share; the editors work on `frameIndex(position, count, morph)` = the nearest table frame, of an expanded one among its 256, and choosing one sets the position where it plays alone, `framePosition`); `$playedWave` (the chart: the frame the position plays, of an expanded table the crossfade of two of its frames; one period, phase 0 to 360°); `$osc` (unison, detune, blend, octave, semi, fine, phase, phaseRand; the pitch over the note is 1200·octave + 100·semi + fine cents, the voices' `detune`); `$unisonShape` (read at note on, not saved); `$gain`; `$params`, the base of the voice params. It sends its table to the engine under its `id` (a new table at once, frame edits at most every `TABLE_THROTTLE` 100 ms) and removes it on destroy. No mod buses: a global source (an LFO) is a source of the core, as the envelopes are.
- The oscillator UI (`synth/oscillator/`): Oct, Semi, Fine are a strip on top of the wave block, under the table (`components/wave/pitch-info.tsx`, `DragValue`s: right or up, 10 px a step, Fine 2; below 380 px `compact`, no carets; the table as wide as the oscillator, its name ellipsized); Semi takes the routes of Pitch, Fine those of Fine, Oct none (no line); each line is its range. Wave frame, Phase, Phase rand and Unison are a strip under the chart (`wave-info.tsx`, `DragValue`: right or up raises it, Phase wraps, Unison with `arrows`; `contain: inline-size`: it never widens the oscillator; below 380 px `compact`). While Phase or Phase rand is held the chart shows the phase and the band [phase, phase + rand) the voices start in, wrapped (`phase-overlay.tsx`). Knobs Gain, Wave, Detune, Blend (`oscillator/index.tsx`; Blend in percent, 75% by default as the reference init patch). While Detune, Blend or Unison is held the chart shows the unison voices over a veil (`unison-overlay.tsx`, a canvas fading out as the phase overlay does: `useFadeOut` of `fade-overlay.ts`; held counted by `useHeld`, two fingers at once, an observable: a press renders the overlay, not the oscillator; Detune and Blend render only themselves on a change, `OscKnob`): a bar per voice, offset by the square root of its cents (±50 at the edges), as high as its level in its channel (at most the chart), centre voices green, the others brighter blue; `unison-voices.ts` places them as the core plays them (detune-mode shares, a random one evenly; the levels of `unison-levels.ts`, `unisonPower` and `unisonPeak` for the bench and the specs; one voice at no spread unless a route raises it; a stack on its steps) and follows the routes of those knobs (`useLiveDraw`).
- `synth.ts` handles voices: a note gets a voice of the voices node (`createVoiceHandle`, `wavetables.createVoice`) with the envelopes, the routes (`voiceRoutes`: the knobs of the oscillators on for it, the filter knobs within its type's range while it is on, amount 0 left out; FX targets go to the fx model; a pitch route moves Semi or Fine within its range from its value: bounds = the knob's range in cents less its value, `pitchesOf`; a change of Semi or Fine re-sends the bounds to the playing notes with such routes, in the message of their detune) and the filter at note on. Playing notes, released ones too, follow Gain, Detune, Blend and Wave (`setTargetAtTime` ~10 ms, then set exactly so the param is constant again), Oct, Semi and Fine (the detune, at once), the routes and the filter (messages, only to the notes whose own routes changed); unison, phases, on/off and the envelopes apply to new notes only.
- A released key sets the gate to `RELEASE_GATE` + the seconds it was held (`performance.now()`), now: the voice is released that long after its first sample (currentTime moves by device buffers, 10 ms on Windows, up to 40 ms on Android: a short note released at currentTime would be released at its start). The fx envelope is released as long after its start on the context clock, not before now and at most `RELEASE_LEAD` (50 ms) after it (`releaseStart`, shared with the processor). A voice processed late posts the frame it started at: from then on the fx envelope starts there (the first voice of a legato phrase moves the phrase's), its release and the end of the release Poly counts are worked out from it (a release already sent moves with it), so are the starts again (mono) made before it (`Voice.startLate`: those before its first sample are its start).
- Poly counts released voices until they end (or their release is over; released where ENV 1 is at 0 it ends there): above it (all of them at once after Poly went down) the quietest released voice is stolen first (ENV 1 now × its amp, `Voice.volume`: a soft note before a loud one; the oldest of equal ones), then the oldest held one.
- Portamento (`glide.ts`): a note pressed while another key is held glides from it (legato too; none at 0), convex in pitch (p₀ + (p₁ − p₀)·(1 − (1 − t/T)²)), there exactly after its time, in 8 `exponentialRampToValueAtTime` of `frequency` (no `setValueCurveAtTime`). Legato (Poly > 1): notes pressed while another is held take the envelopes and the start of the phrase (no retrigger); each releases at its own key.
- Mono (Poly 1, `Voicing.mono`: one voice and the stack of held keys, the last pressed on top): a note while the voice sounds takes it over (the key moves; phases, filter and mix tables go on). Over a held key it glides from where its pitch is (an interrupted glide holds at the point of its own line, `glideFrom`, not `cancelAndHoldAtTime`); in legato the envelopes go on, else they start again (`Voice.retrigger`: the gate held at its other value now, each envelope from its level; two notes at one currentTime keep the value); from its release (no key held) the pitch steps and they start again. Releasing the top key hands the voice back to the key below as if it were pressed, releasing a key below changes nothing, the last key releases it (h from its last start). A new voice instead (the old one stolen) when its release ends within `RELEASE_LEAD` (it would end before it sees the gate) or it would start envelopes other than the knobs' or play other oscillators (`Voice.playsKnobs`: on/off, the unison and its shape; not the phases). A mono voice has a phrase of its own. Poly reaching or leaving 1 while notes play: the voice plays on as a voice of its note, the next note follows the new mode; a mono voice that ended by itself: the next note starts one.
- `$fxNote` is the envelopes of the last note pressed (legato: of the phrase, released with its last key; mono: a start again is a new note from then, `from`: the levels its envelopes start their attacks from); the fx follow it.
- Every voice stays `sounding` (it follows the knobs, a preset switch waits for it) until the voices node reports it `ended`; no events are sent for an ended voice. A voice that traps in the node ends alone: the facade catches the trap (the stack pointer put back), the voice gives its tables back, is reported ended and its block output is left out of the sum (the stores of the scope before it are in memory: a `compiler_fence` before each voice); the others render on, the engine stays ready. A note on that traps is reported ended too, so is a voice an event finds no memory for (its timeline can't grow); a message call that traps (routes, filter, a batch of events) loses only what it carried, the later events are applied (`guard` of `apply`); an event of a param the core hasn't got is nothing. A held voice that ended so frees its key: Poly doesn't count it, no glide starts from it, the fx release their envelopes then (`letGo`).
- The pitch bend is the voices node's (`setBend` of the engine, one `bend` event for every voice: `bendCents` = 100 · its share × the range down or up, `v.bd`/`v.bu` semitones 0..24, 2 by default; at most every `BEND_INTERVAL` 5 ms, `throttleTime`: the first at once, the last after the pause): the scope glides there in 10 ms (`Glided` of `glided.rs`: a glide ends by its samples; a non-finite bend is the rest, `set_bend`) and puts it on the detune of both oscillators of every voice, released and new ones too (`bend_into` of `scope.rs`; at rest nothing changes); a node made again (Retry) takes it at once (`instantly`). The octave of a detune steps at once, under the bend. While it moves each voice plays a mix whose reach holds its pitch, else directly; at rest it takes its own mix again.
- The velocity of a note goes in its options (`velocity`: VELO by the curve of the env model at note on, `velocityLevel`, and its amp, `velocityAmp`); the voicing keeps the velocity of each key held or waiting (the mono stack, a preset switch); a mono note that takes the voice over (or the key below given it back) sends its velocity (`setVelocity`: VELO and amp glide there in 10 ms) and the fx follow it.
- A preset switch silences the synth (`sound-switch.ts`, the `soundSwitch` model: the synth core, the synth, the fx and both oscillators; `switchSound(apply)`): two presets never mix. The output fades out (`mute`) in `KILL_FADE` (20 ms, a stolen voice's fade) and the synth pauses (`pause`: every voice fades out, the fx follow no note; the held keys (mono: its stack) and those pressed meanwhile wait, a released key leaves them). Once `currentTime` is past the fade and the faded voices have ended (polled every 10 ms; a context that isn't running isn't waited for; a clock that doesn't move: 200 ms at most, `MAX_CLOCK_WAIT`, after the preset too) the preset is applied (the chain rewired then doesn't click), then the fx and the limiter forget the sound before (`clear`); a preset chosen meanwhile replaces it. The output steps back to 1 (`unmute`: a fade would take the attacks) `SWITCH_LEAD` (10 ms: the clear messages reach the worklets first) after it, once the oscillators on play the tables of their paths (`tablePlayed` of the oscillator model: not loading nor `sending`; refused or failed: the version before plays), 2 s at most (`MAX_SILENCE`). A preset that throws as it is applied doesn't keep the synth silent (its error goes on to the caller of `switchSound`, uncaught from the poll; the fx and the limiter are cleared all the same). Then the keys still held start on it (`resume`: in their order, no glide between them; mono: the last one, the others under it in its stack). A preset chosen while silent is applied at once and the wait starts again.

### Tempo, envelopes, modulation, LFOs, input

- The tempo (`synth/common/modules/transport.ts`, the `transport` model; `transport/tempo-map.ts`, no imports): `$bpm` of the field (20–300 BPM, steps 0.01, `tempoOf`; localStorage `tempo`, not in a preset; 120 where the storage keeps nothing), `$tempo` in effect (the field's, or a MIDI Clock's: `$source` `midi`, not kept), `$playing` (a MIDI Start to its Stop). The transport is beats (quarter notes) on the context clock, beat 0 at time 0 (the first anchor of an LFO): the newest 4 segments `{ time, beat, bpm }`, `beatAt`, `timeAt`, `tempoAt`; a new tempo is a segment from now + `LFO_LEAD` at the beat there (the grid goes on), at most every `LFO_STATE_INTERVAL`; `locate(beat, at)` moves it (MIDI Start, Song Position), `follow` sets a segment of a MIDI Clock on its line (not before now + `LFO_LEAD`), `$changes` emits each new segment. It is set in the Settings popover (desktop and phone; `settings/tempo-display.tsx`): a seven-segment display (`SegmentDisplay` of ui-kit: SVG cells, unlit segments faint, decimals smaller), dragged up or right 1 per 4 px (Shift: 0.01 per px), ▲ ▼ step 1 (Shift 0.01), a double click types into its cells (3 digits, the point, 2 decimals; a hidden input: Enter or a click elsewhere takes it, Escape doesn't), within 30–240; led by a MIDI Clock it shows its tempo to 0.1 with EXT, read-only.
- Divisions (`libs/preset-schema/src/tempo.ts`): `TEMPO_DIVISIONS` Off, 32 bar … 1 bar, 1/2 … 1/256, their triplets (×2/3) and dotted ones (×1.5), then 1/512 (appended: no triplet nor dotted), a bar of 4/4; a preset keeps an index (append only). `divisionSeconds`, `nearestDivision` (by the ratio of lengths), `divisionWithin` (a triplet or dotted one a knob hasn't got: its straight one); knob steps: `rateDivisions` (TRIP, DOT), `ENVELOPE_TIME_DIVISIONS` (Off, 1/512 … 32 bar), `TIME_DIVISIONS` (Off, 1/256 … 32 bar: Delay and Rise of an LFO), `delayDivisions` (1/64 … 1 bar, TRIP, DOT). A knob in BPM is a `Handle` with `step` (precision 1); its routes, marks and arcs are its target's, moving the value in the units of HZ (`modTravel` of `Handle`; `useStepTravel` of `modulation/step-travel.ts` puts the arc and mark on its steps at the tempo). The seconds of divisions are worked out on the main thread: the LFO wire, the envelopes of a voice and the cores know no divisions.
- Envelopes (`synth/common/envelope/`): `envelope-curve.ts` (no imports; shared by the worklets, the main thread and the specs) is an envelope as a function of time, the release from the level reached to 0 in its time; attack, decay and release are linear or curved by `curves` (k of `curveShape`: (1 − e^(−k·x)) / (1 − e^(−k)) over the share x of the stage). Curves are in the preset (`curves: { attack, decay, release }` per envelope, k within ±`ENVELOPE_CURVE_MAX` 10); a fresh envelope has `ENVELOPE_CURVES` of the schema (a linear attack, decay and release at k 3.49: `envelopes.json`, whose curves 25/50/66.6/75% are k −5.41/0/3.49/5.41 within 1%); a note takes them with the knobs at note on (the voices, the fx note, the marks; mono starts a new voice for other curves). The voice renders a curved stage by a recurrence (e^(−k·x) times a factor per sample, `envelope.rs`; a block within a flat stage is one value); fx-mod lines read it at their points; voice modulation reads the envelopes every 32 samples; started again on a sounding voice (mono) its attack goes from the level reached (`from`) to 1 in its time, its stages ending where a new note's would.
- The envelope chart draws the curve (`envelopeLine` of ui-kit, `envelope-line.ts`: `CURVE_POINTS` per curved stage, squares at the corners) and, on each stage longer than 20 ms (`CURVE_HANDLE_MIN_TIME`; none on a decay to a sustain of 1 or a release from 0: `CurveHandles` of `curve-handles.tsx`), a point in the middle of the stage on its curve, where the share done is 1 / (1 + e^(−k/2)): dragged it follows the pointer (`curveFromMidShare`: k = 2·ln(s / (1 − s)), steps of 0.01), snaps to k 0 within 3 px of the line, ↑/↓ move it, a double click restores the default curve. The chart of the open tab has a dot of the last note pressed (`EnvelopeDot`: `$fxNote`; ENV 1 always, ENV 2 and 3 while a route reads them), whose path (`noteCorners` of `note-path.ts`, 16 points per curved stage) is always on the chart's line (a knob turned while the note plays moves the dot with the line): released before the sustain it steps to the sustain corner, then follows the release line; an envelope started again starts on the attack line at its level. It is one Web Animation of transform and opacity of an HTML element (`NoteDot` of ui-kit, in the `overlay` of `LineChart`), started where the output plays the note's start (`outputTime`: `getOutputTimestamp`, else the latencies of the context): the compositor moves it, no frames on the main thread; finished on the sustain, hidden after the release (fill none: a longer release turned later doesn't bring it back); remade only on a note on or off, another tab or new scales.
- MS/BPM per envelope (the key `BPM` right of Release, a square as large as its knob with its arc: `aside` of `AdsrEnvelope`): in BPM its times are divisions (`divs`, `ENVELOPE_TIME_DIVISIONS`; `timeSteps` of `AdsrEnvelope`: the knobs step through them, the chart and the dot draw their seconds at the tempo); MS → BPM takes the division nearest to the seconds at the tempo, BPM → MS their seconds (32 s at most). A note reads the seconds at note on (`envelopeSeconds`: a new tempo applies from the next note on; a stage may exceed 32 s, 32 bars at 20 BPM are 384 s; mono starts a new voice for other seconds, `sameEnvelopes`: in BPM within `TEMPO_SLACK` 1%, since a MIDI Clock moves the tempo by hundredths).
- The `env` model (`envelopes.ts`, snapshot `env: { e1, e2, e3 }`, stages 0..32 s, `ENVELOPE_DEFAULTS` of the schema, `setEnvelopeCurve`) holds ENV 1–3 (time knobs `mode: 'pow'`), the velocity knobs (`$velocity`: Amp, the share of a note's volume it takes, `1 − Amp + Amp · VELO`, and k, the curve of VELO over velocity / 127; snapshot `vel`, `VELOCITY_DEFAULTS` Amp 1 and a line; read at note on), the selected tab (`$selected`, a `ModSource`, not saved) and the envelope the ENV section shows (`$envelope`, the last one selected: it stays while VELO is selected). VELO is a section of its own right of the LFOs (`velocity-section.tsx`): `VelocityCurve` of ui-kit (the curve with one `CurvePoint` in its middle, a double click makes it a line), the dot of the last note on it (`$fxNote.velocity`), the Amp knob.
- Layout (`synth/index.tsx`): the oscillators and the filter on top (3fr 3fr 2fr), the row under them 1.6 : 1 lower: ENV 3fr, LFO 3fr, VELO and Voicing 2fr between them (a grid of their own: the lines of both rows meet); the FX screen takes only the top row (scrolled), the row under it is the same element on both screens; phones in the same order (`mobile/synth-sections.tsx`).
- Modulation: the `modulation` model (`modulation.ts`; snapshot `mod: { 'env2:osc1.wave': 0.5 }`, bipolar `{ 'lfo1:filter.gain': { a: 0.5, bi: true } }`, switched off `{ a: 0.5, off: true }`, with `bi` too; one route per source and knob, at most `MOD_ROUTES_MAX` 64 in all and `MOD_KNOB_SOURCES_MAX` 4 per knob: past them the knobs, or the full one, take no tab and don't light up) holds the routes: amount −1..1, a share of the knob's range in its scale (octaves for a log knob, a share of the travel of a pow one, `amountInUnits`), uni (amount × level) or bipolar (amount × (level − ½)); `addRoute` makes an LFO route bipolar on a knob centered on 0 (`centered`: the filter gain, the delay pan, Pitch, Fine), an envelope or VELO route uni (at rest the knob is its value); `setPolarity`.
- `modulation-targets.ts` registers the targets: `osc1.gain|wave|detune|blend|pitch|fine` (Blend → `blend1` of the voice, 0..1; Pitch and Fine → the offsets `pitch1`, `fine1` of the detune, a share of the range of Semi, 48 semitones, [−2400, 2400] cents, `SEMI_MAX`, smoothly, and of Fine, 200 cents, within it from the value: `knob` of the target, Semi 0 at 100% −24..+24, Semi −24 −24..0), `filter.cutoff|resonance|gain` within the filter type's range, `<fx>.<param>` and `<fx>.mix` for every knob of `FX_REGISTRY` (not the switches), `lfoN.rate|delay|rise|smooth|phase` (no LFO goes there: `takesSource`).
- Source tabs (`modulation/source-tabs.tsx`, `SourceTabs`): ENV 1–3 in the ENV header, VELO in its own, LFO 1–4 in the LFO header (`MOD_SOURCES`; `accepts`: LFO tabs light no LFO knob); a segmented control, an equal share of the header each (`Section plain`: no header padding, the tabs on its grey). Colors (`SOURCE_COLORS`): ENV 1–3 green, blue, violet, VELO gold, LFO 1–4 rust, plum, cyan, pink; any two ≥ 18 apart in OKLab (×100), 9.7 for protanopia and deuteranopia, lightness 0.49..0.68 (OKLCH), the white count readable on each. A tab: a dot of its color in a white ring before the white label, the number of its source's routes in it (adding or removing a route renders the tabs, not an amount); the selected one a white key with a dark label and a grip in its right corner; the envelope the ENV section shows while VELO is selected a translucent key; no focus outline. Tabs are dragged onto knobs (`startModDrag` of ui-kit, pointer events): a drop adds a route at +50% and selects the tab.
- `useKnobModulation(target)` gives a knob its `modTarget` and `modulations` (all its routes in source order; `selected` the selected tab's route, `$selected` of the env model: only it shows its arc; the dot at the top left shows all of them and changes it, dragged it changes the amount). Every route moves the live mark where the routes move the knob in the last note while voices sound (an effect knob an LFO moves, without a note too, while the effect is in the chain and on; the LFOs of the last note: `noteLfos` of the synth model, `noteLfosOf` of `modulation/note-lfos.ts`, following `$fxNote` and the routes by the synth's subscriptions, so a synth made again leaves nothing behind); only a knob with routes renders, when the first voice starts and the last one ends. Shift+Alt+click on the knob or Shift+click on its dot switches the polarity of the selected route (a bipolar arc is ±amount/2 around the value). The knob's menu (`useControlMenu` of ui-kit) changes each route's amount (its row dragged), switches it on or off (`setOff`), its polarity, removes it or all of them (`removeRoutes(target)`, `onClearModulations`), and sets the knob's default. A route switched off keeps its amount and polarity, counts in the limits and the tabs, and moves nothing (`voiceRoutes`, `fxRoutes`, `lfoKnobRoutes` leave it out; the dots of ENV 2/3 and of the LFOs, the hook's `live` and the marks (`liveRoutes`) don't read it: `readsSource`). The knob charts follow the routes too (`useLiveDraw`, nothing while their section is off): the wave (`osc1.wave`: the frame played; the phase band and dot on its overlay canvas), the filter response (cutoff, resonance, gain), the distortion curve (Drive), the reverb decay (Size, Decay, Hi damp, Bass), the delay bandpass (Freq, Q).
- FX modulation (`fx/effects/fx-modulation.ts`, shared by the main thread and the worklets; VELO of the last note, `$fxNote.velo`, is one level throughout: `noteLevel` of a source past the envelopes): the fx model gives each effect `{ note: $fxNote, routes }` while it is in the chain, on and ready (null otherwise: nothing computed) — the envelopes from `note.from` once a mono note restarted them; with an LFO route also the note's routes to the LFO knobs (`lfoKnobRoutes`); no note yet or paused: only the LFO routes, on their clocks — and every LFO state (`setLfos`). Distortion and reverb compute the moved knobs once per block in their worklets (`modulate` of `registerStereoProcessor`: `createFxModulator`, the LFOs of the note stepped to the block in points of 32 samples, `createNoteLfos`; it holds back posted values of moved knobs and sets a value only when it changed; the reverb's Size and Predelay then glide in 10 ms without their tape glide, its lines follow a moved Size; a node made later takes the LFOs in `processorOptions.lfos`).
- Knobs of native nodes (the delay: Time on both lines, Feedback on a line's gains into itself and into the other, a line each, while its mode is on and the delay active (another mode glides one out and the other in), Pan on each side's delay, Freq and Q k-rate; the dry and the wet gain of every slot) follow their routes by the lines of the fx-mod worklet (`fx-mod.ts`, `fx-mod.worklet.ts`, `fx-mod-lines.ts`, `fx-mod-params.ts`: one node of the fx model, no input, an output channel per line, `FX_MOD_LINES` 13): the offset map(knob moved) − map(knob) (`mapKnob`: the pan split at 0, equal power or linear mix) at points every 32 samples and the last of a block, linear between, added to the params, which stay at the knobs with their glides (Time with its tape glide; a message a quantum late only shifts the offset's start); a change (a route, a knob, a new note) glides from where the line was in 10 ms (`FX_MOD_GLIDE`); a line gone glides to 0 and is then disconnected (connected only while it has routes: an a-rate input costs every sample); until fx-mod is ready no route moves them, the knobs work. `fx-automation.ts` only steps and glides the knob params (routes have no automation: the corners of an envelope couldn't lead an LFO, and timers throttle in a background tab). The osc/fx switch (`TapeSwitch switchOnDrag`) flips when a dragged label stays on it 600 ms.
- LFOs (`synth/common/lfo/lfo-curve.ts`, no imports but the envelope curve, shared by the main thread, the fx worklets and the specs; the core `lfo.rs` does the same operations in the same order, except for a route of Rate: its base in f32 as the routes read it): LFO 1–4, route sources 4–7 after VELO, each a cycle of its shape every `rate` seconds (the period, 10 ms..32 s; the knob goes by the frequency, right faster, and shows the period). A shape is a table of `LFO_TABLE_SIZE` 2048 + 1 levels 0..1 the TS builds (`lfoTable` of sine, triangle, saw up and down, square, or of `points` [x, y, k] of its own: the curved segments of the envelopes, the last one over the end of the cycle; `lfoTableFrom` any cycle). The Shape select offers them by category (`synth/lfo/lfo-shapes.ts`: Basic the shapes; Sidechain, Rhythm and Steps points (`setPoints`: the preset keeps them, a change of the list changes no sound); others Custom; `shapeOptionOf` within the 4 digits of a preset).
- Clock: the anchors of the main thread (`nextAnchor`: a new period from now + `LFO_LEAD` 10 ms at the phase there, no step; the newest four kept). A note runs an LFO from the start of its envelopes (`createLfoRunner`, `LfoBlock` of the voice, at the route points: every 32 samples and the last of a block): during Delay the left point of the shape (its level at the cycle's start; tD the first point past s + Delay), Rise morphs it into the shape linearly, Smooth lags it by one pole (seconds; its coefficient by the frames between points), Phase shifts the cycle (around it; a new one glides the shortest arc in 10 ms); retrig plays the cycle from tD (φg(t) − φg(tD) + δ), free the clock (φg + δ); the mode is live (a playing note switches at once, as if it had played the other one all along); δ is the phase a route of Rate adds (∫ of the frequency it moves to − the knob's, from tD). A new shape crossfades in 10 ms from the one playing at its time; until then the crossfade before goes on (`pending` of `createLfoGlobal`, `pending_table` of `lfo.rs`: a third shape meanwhile takes the waiting one as played from now on; the mixes are baked into two buffers of the global, the tables are the states': a state allocates nothing on an audio thread). A legato note starts them where the phrase does, a start again (mono) restarts them (retrig from 0, Delay and Rise again, the smoothing goes on), a late voice at its first sample. One LFO per note, not per unison voice, running in the release too.
- LFO knobs take the envelopes and VELO (`lfoN.rate|delay|rise|smooth|phase`: Rate in octaves of its frequency within 1/32..100 Hz, the times a share of their travel, `pow`: max · (share + Σ)⁴, Phase around the cycle, not clamped), no LFO (the schema, the model, the drag and the core drop it).
- BPM (keys right of Mode on one plate, `SwitchKeys` of ui-kit: `BPM`, HOST an anchor, triplets and dotted as notes with a 3 and a dot, `icons.tsx` of `switch-key/`; HOST dimmed in Retrig, T and D in HZ): in BPM Rate, Delay and Rise are divisions (`div` with TRIP and DOT, `delayDiv`, `riseDiv`), their seconds at the tempo on the same wire (no ceiling: 32 bars at 20 BPM are 384 s). The steps of Rate are those at least `LFO_RATE_MIN` long at the tempo (`rateStepsAt`: 1/256 is shorter above 93.75 BPM; the same steps, the same array); a shorter division kept by a preset plays the shortest step (`lfoDivision`: the knob shows it, HOST is on its grid, a slower tempo plays its own again). HZ → BPM the nearest divisions (Rate among its steps at the tempo), BPM → HZ their seconds. A new tempo is an LFO state in BPM from its segment on (a period of its own, the phase continuous: `nextAnchor`); a free one with HOST is on the beat grid (`anchorOf`: its phase the share of its division since beat 0 at every segment; a new Rate may step it there), in HZ its phase is the transport position in seconds where it moves (`locate`: a MIDI Start); retrig takes nothing of HOST. Routes to the LFO knobs in BPM are bounded by the divisions at the tempo (`$ranges`, `lfoRanges`: Rate from the longest to the shortest step, Delay and Rise up to 32 bars; amounts in the units of HZ: the cores take a pow bound as its travel, so a Delay or Rise amount goes as (32 s / bound)^¼, `routeAmount` of `modulation-targets.ts`), sent again to notes that have them on a new tempo (as `movesPitch`).
- The `lfo` model (`lfos.ts`, snapshot `lfo: { l1…l4 }`, `LFO_DEFAULTS` a sine of 0.5 s, retrig; `$selected` the tab, not saved) sends every change as a state from now + 10 ms, at most every `LFO_STATE_INTERVAL` 20 ms (`throttleTime`: the first at once, the last after the pause; a drag posts at most 50 states a second to five threads, 8 KB per shape table; a shape never comes while the one before still crossfades). A state (`LfosState`: the knobs, the newest anchor of each clock, the tables of changed shapes; `$changes`, `$state` with every table) that reaches an audio thread late takes over at its next block (`lateState` of the voices processor, the fx worklets and fx-mod: its Phase still glides, its shape still crossfades, its anchors keep their times). It goes to the voices node (a `lfos` event, in order with the others), to the fx and their worklets, and runs on the main thread (`globals`). A consumer takes states only while it reads an LFO (`createLfoFeed` of `lfo-curve.ts`: the engine while a voice has an LFO route, `lfoVoices`; reverb and distortion while their modulation has one, fx-mod while a line has); meanwhile states are merged on the main thread (`mergeLfos`) and the LFOs as they are go first, instantly, before the message with the route; a node made later (ready, Retry) starts with them (`initial`): every audio thread deserializes a state and allocates its 8 KB table.
- In the core the LFOs of a node live in the shared (`LfoGlobal` × 4: the clock, the knobs from the time of a state on, the shapes; `osc_shared_lfo_table`, `osc_shared_lfos`; a state wakes the voices' routes, `lfo_epoch`); a voice runs those a route of a param reads (`modulation.uses_lfos`; a second `Modulation`, `lfo_mod`, moves their knobs; one value in its Delay or on a flat shape: the voice stays on its mix tables); without an LFO route none of it runs. The fx follow the LFOs of the last note (`createNoteLfos`: from its start; without a note on their clocks, Delay and Rise passed), the knob marks and the chart too.
- The LFO section (`synth/lfo/`, right of ENV): tabs LFO 1–4; one cycle of the shape shown 4 px in on every side (an editor point whole) on the lines of an envelope chart (levels 0, ½, 1, the quarters) with the dot of the last note (`NOTE_DOT_RADIUS`/`NOTE_DOT_COLOR`; `onFrame` of ui-kit on a canvas, no render; cleared without a voice) and its points, edited there (`lfo/components/lfo-points.tsx`; the math in pure `lfo-edit.ts`: a list the model takes, or null). A point drags within its neighbours (onto one: a step; the first stays at x 0; x and y to 0.001, `movePoint`); each rising or falling segment at least 12 px wide has a curve point, the last one to the cycle start too (`CurvePoint` of ui-kit; `setCurve`); a press within 6 px of the line (`nearestSpot`: the projection on the nearest segment of the chart's 257 samples, a vertical one a step; a translucent point shows it, cursor copy; points filled, curve points hollow; not within a point's hit area nor at `LFO_POINTS_MAX`) adds a point there (`insertPoint`: on its segment's curve, which keeps its shape exactly: an exponential segment over a part of it is one of k × the part's share, `envelopeCurve`) and drags it on; a double click removes a point (`removePoint`: two stay, the first too; the segment before keeps its k). A preset shape shows as points too (`shapePoints` of `lfo-shapes.ts`: triangle, saws and square exactly, the sine as four curved quarters of k ±1.7, within 0.022) and becomes those points on the first change (`setPoints`: Custom in the select); every change sends the table to the audio threads (the sound follows the drag). Shape and Mode; knobs Rate, Delay, Rise, Smooth, Phase (targets). Specs: `lfo-curve`, `lfos`, `lfo-edit`, `lfo-points`, `lfo-shapes`, `lfo-chart`, the `LFO` describe of `wavetable-osc-dsp.spec` (a voice against one given the levels of the TS runner, to 1e-6), `lfo.rs`, `modulation.rs`, `tests.rs`, the LFO goldens, `fx-modulation`, `fx-mod-dsp`, `fx-mod`, `lfo-section`, `use-knob-modulation`.
- MIDI Clock (`transport/midi-clock.ts`, pure). `midi-controller.ts` takes the system messages of the selected input before the length and channel filters: 0xF8 a clock, 0xFA Start, 0xFB Continue, 0xFC Stop, 0xF2 Song Position (16ths); each at the moment the page took it (`messageTime`: Chrome stamps MIDI messages 0, a stamp later than now or older than 1 s is none); the context time the output plays then is used only for the segments (`contextTimeAt`: a suspended context's clock stands). From its first clock it leads (`$source` `midi`): its tempo is the slope of the lower envelope of the last 96 clocks (4 beats, 24 a beat; a beat of them at least; clocks come late by the main thread's tasks, 0..70 ms in Chrome, never early: the least late of the first and last third, `fit`; within 0.1 BPM on a DAW's clocks through IAC that Chrome took, `midi-clock-arrivals.json`; within 20..300, a faster DAW plays at 300; none over `CLOCK_TEMPO_MAX` 1200 BPM: clocks the page took at once after a stall), shown to 0.1; a segment where the transport is more than 1 ms off the clocks or its tempo 0.05%, once a beat at most. Start (beat 0) and Continue (where it stopped, or a Song Position) take the transport there at the next clock; Stop holds the position (`$playing` false, the LFOs go on). The clocks before a Start, Continue or Stop are not on the line of those after (a DAW restarts them there): the window starts again, its first beat at the transport's tempo. 500 ms without a clock (`CLOCK_LOST_MS`, `lose`): the field's tempo leads again, the position of the next Continue is kept. Another input (`reset`): nothing of the clock is kept. Sync to MIDI Clock in the Settings popover (WebMIDI only; `$clockSync` of the MIDI controller, localStorage `midiClock`, on where the storage keeps nothing): off, the clock, Start, Continue, Stop and Song Position are ignored (the notes play); switched off while it leads acts as another input.
- `input-controller.ts` is the shared note bus: `$onPress` carries the note and its velocity (MIDI 1..127; QWERTY and the piano play `DEFAULT_VELOCITY` 100), `$bend` the pitch bend as a share of its range (−1..1, 0 at rest; the last of MIDI and the wheel wins). The on-screen piano, `keyboard-controller.ts` (QWERTY) and `midi-controller.ts` (WebMIDI) feed it.
- The MIDI controller passes the velocity of a note on and the pitch bend of its channel (`0xE0`, `midiBend`: 14 bits, 8192 at rest, 8191 steps up and 8192 down; one within `BEND_NOISE` 2 steps of the last it set on its channel moves nothing while that one plays: a wheel's noise would take the voices off their mix tables; rest and the ends come exactly) and puts the bend it set back at rest where it releases its held notes (another channel, input or none; the wheel's bend stays). The chosen MIDI input and channel are kept by the tab (sessionStorage `midiInput`, `readStored`/`writeStored` of `app/common/services`): the chosen input is selected whenever connected, meanwhile the selected one while it is, else the first one (selected for the user, not kept).
- QWERTY notes are ignored while focus is in a text field (`keyboard-controller.ts`); a keyup releases only the note its key pressed, whatever the modifiers (not one of MIDI or the piano); a note two keys hold (the octave shifted between them, Comma and Q) is pressed by the first and released by the last; all of them are released when Cmd is (macOS sends no keyup of a key let go while Cmd is held) or the window loses focus (`$blur` of the app model); auto-repeat presses nothing. The octave of the computer keyboard (`$octave`: Z = C{o}, Q = C{o+1}, ] = G{o+2}; 0..6, 3 by default, `KEYBOARD_OCTAVES`; localStorage `keyboardOctave`, not in a preset; MIDI is not shifted) moves its notes from the next keydown (a key held across a shift releases the note it pressed): ▲ C3 ▼ of the desktop (`OctaveControl` of `app/common/components` in the row of the wheel and the keys, `synth/piano/`; the phone tiers have their own; its carets are `CaretButton`s as the tempo's: a press takes no focus, `keepFocus` of ui-kit) and ↓ / ↑ (a step a press, not with Cmd or Ctrl, nor where the focused control takes the arrows: a text field, a select, a dialog (its lists scroll), or a control that prevented them already, as every control of ours that steps by the arrows does, antd's tabs and a keyboard drag of the effects too: they are listened on the window, `$windowKeyDown` of the app model, after every listener of the document, where dnd-kit adds its own as it drags); the desktop piano follows it from the octave under it (`pianoOctaves` of `synth/common/piano-octaves.ts`: 2–6 by default, within `PIANO_OCTAVES` 0..8, the phone tiers too). The on-screen piano releases a key on blur too, and on a pointer that moves without a button (its pointerup lost).
- The wheel (`synth/pitch-bend/`, `PitchWheel` of ui-kit: a dark drum in a slot, as high as its place, its ribs and mark where they are as it turns, ±60° over the range, the mark follows the pointer; it shows the bend once a frame; a drag compares with its own last value, not the one shown a frame late; its section is memoized: the keys render on every note) springs back to 0 when let go, on blur and on a lost pointerup. Desktop: a section of its own left of the keys, with its range Up/Down and the octave of the computer keyboard between them, the bottom row as high as the keys (`KEY_HEIGHT`; the keys narrower to fit). Phone: alone (its range is the preset's) in the column left of the keys (`keys-view.tsx`): in portrait under the octaves of both tiers, in landscape left of both tiers, as high as them.

### Rust cores of the worklets (dsp/)

- The DSP of the worklet modules is Rust → wasm32, one `.wasm` per worklet bundle (`dsp/<crate>`, a cdylib with a C ABI, no wasm-bindgen and no SharedArrayBuffer): the limiter (`dsp/limiter`), the reverb (`dsp/reverb`), the distortion (`dsp/distortion`), the wavetable oscillator with its store (`dsp/wavetable-osc`). A bundle `<name>.js` (`<name>.worklet.ts`) registers its processors (names in `common/processors.ts`) with their messages, its facade (`<name>-wasm.ts`) wraps the core; the options and messages are in `limiter-params.ts`, `reverb-params.ts`, `distortion-params.ts`, `wavetable/voice-options.ts`. A module with a core needs wasm SIMD (`isWorkletSupported(ctx, name)`, `WASM_MODULES` of `common/wasm/wasm-support.ts`: `unsupported` without it, the limiter and the oscillators silent).
- The crates: `jsmath` (the Math of JS bit for bit: V8's fdlibm of `deps/v8/src/base/ieee754.cc` for sin, cos, exp, expm1, tanh, log, log2, log10, glibc's pow without FMA, as V8 calls std::pow; `round`, `max`, `min`, `to_int32` with the JS semantics; `jsmath-check` exports it to the specs), `dsp-core` (biquad coefficients and TDF2, the blocks of the effects, true peak, oversampler, the stereo io; `consts.rs`: tables as the bits of each double; `simd.rs`: `F64x2`, two independent lanes, the operators of f64 and the `min`/`max` of wasm, which are those of Math; `stereo.rs`: biquad, DC blocker and oversampler of both channels in the lanes, `LaneBiquad` two filters of coefficients of their own; `blocks.rs`: `DelayLine::read_pair`, `Allpass::process_pair`, two lines in the lanes with their hermite indexes as integers, ToInt32 once, `StereoDelayLine`, `StereoFixedAllpass` a ring of both channels). `cargo test` runs the lanes as arrays (`simd.rs` off wasm): the crate specs hold each lane to the scalar block, only the goldens in Jest run the SIMD of wasm. On wasm32 the crates are `no_std` (`wasm-rt`: a panic traps, dlmalloc; `jsmath::floor/ceil/trunc/sqrt` are the wasm instructions), natively std.
- `dsp/rust-toolchain.toml` pins the toolchain, `.cargo/config.toml` builds with `+simd128`, a 64 KiB stack and `__stack_pointer` exported: a trap leaves it moved (about 70 failed note ons used up the stack), so every call of a core puts it back (`instantiateCore` wraps the exports; the calls of a block guard it where they are made: `fx_buffers` and `fx_process` in `stereo-core.ts`, `osc_io` and `osc_voice_process` in the voice, `osc_scope_process` and `osc_scope_resume` in the scope). A trap pins nothing: `Voice::new` only allocates, `attach` joins the phrase and takes the versions once the voice is boxed (the scope reserves its place before), its end gives the versions back before the mixes, a mix without memory plays directly, the store reserves the room of an entry before it takes a slot and never traps holding a buffer. `panic = "abort"`, fat LTO.
- The sound: the cores were ported bit for bit from TS cores (since removed) and compute every value in a fixed order: no `mul_add`, no fast-math, no relaxed-simd; SIMD only over independent lanes, sums in their order, `as f32` where the TS wrote into a Float32Array, the Math of jsmath ("as the TS" in a comment of a crate names such an order). The goldens hold it: `<module>-goldens.spec.ts` renders the golden scenarios block by block (their hashes in `dsp/goldens/<module>.json`; a change of the sound is an explicit `UPDATE_GOLDENS=1`) and random ones (`test-utils/fuzz-signals.ts`, `FUZZ_SCALE`; the nightly run × 250): finite, never over the ceiling of the limiter, every voice ending and giving its tables back. Node's own Math differs by machine (on arm64 its fdlibm is compiled with FMA contraction, its pow is the libm of the system), so the goldens specs import `test-utils/js-math.ts` first (Math becomes jsmath; `**` runs as `Math.pow`: the babel plugin of `jest.config.ts`); `jsmath.spec.ts` checks jsmath against Node (x64 bit for bit, arm64 within 4 ulps) and against the hash of its outputs. The DSP specs of a module (`<module>-dsp.spec.ts`) run its core through its facade. The specs load `tmp/wasm-perf` (`test-utils/wasm.ts`; `wasm-babel-plugin.js` reads the bytes a bundle imports, `import bytes from '@chisper/wasm/<name>.wasm'`: Jest loads any `.wasm` file as an ES module): `npm run wasm` first.
- The wavetable oscillator (`dsp/wavetable-osc`: `envelope.rs`, `lfo.rs`, `modulation.rs`, `filter.rs`, `velocity.rs`, `glided.rs`, `store.rs`, `shared.rs`, `voice.rs`, `timeline.rs`, `scope.rs`): one instance per AudioWorkletGlobalScope holds the store, the shared and the voices (handles: `osc_store_new`, `osc_shared_new`, `osc_scope_new(rate)` the voices of a node with the ranges of the params, `osc_voice_new(rate, store, shared)` a voice alone, the facade of the specs; the specs make several stores and shareds in one instance). The scope (`createVoiceScopeWasm`): `osc_scope_on` (the options of a voice and its values in `osc_command`), `osc_scope_events` (the automation events of a message, 6 values each), `osc_scope_routes`/`osc_scope_filter`/`osc_scope_velocity`, `osc_scope_bend`, `osc_scope_process(frame, frames)` (every voice: its 12 timelines or the arrays of `osc_scope_direct` (the specs), then `Voice::process`, added to the sum at `osc_scope_output`), `osc_scope_fail` and `osc_scope_resume` (a voice that trapped ends, the block goes on with the next one; `fail` is false when the trap was not in a voice: the block is silence), `osc_scope_reports` (the starts and the ends since the last call), `osc_scope_tap`/`osc_scope_taps` (the output of every voice apart: the goldens of the scope, the parity of the browsers), `osc_scope_stats`, `osc_scope_free` (its voices end).
- The store: the versions of a table live in the memory of the core (a slab, refcounted: `EntryRef`); a version no one holds gives its buffer to a pool (2 at most, the samples of one table of 256 frames at most): the smallest buffer of it that holds a table takes it, none does: the pool is freed before one is allocated (two sizes in turn: the memory stops growing after the first switches; a table that grows a frame at a time to 256 takes 239 MiB: two versions of up to 63.6 MiB live while the next comes, and what dlmalloc can't join); the placeholder sine is the store's. A table arrives in chunks: the store posts `{ chunks: STORE_CHUNK }` (1 MB) to the worker once it has its port, the builder (`wavetable-builder.ts`) then sends `begin` (the layout: `osc_store_begin` only reserves the room of the version) and the data chunk by chunk (`osc_store_chunk` gives the room of each in order and within the length of the version, zeroing only the chunk; `commit` refuses a version a chunk of which is missing), the next once the store acked the last with its buffer (`createStoreReceiver`: a chunk is acked whatever happens to it, one that fails aborts its version, `osc_store_abort`, refused; the worker sends `{abort}` for a version it stopped sending; the port of a new worker aborts every slot and the receiver before it drops what still comes, `epoch`), then frees its levels at once (`transfer(0)` detaches their buffer: kept for the next build or left to a GC of the idle worker; Safari before 17.4 leaves it to the GC), and the store replies nothing freed; a version the core has no memory for is `refused` (`try_reserve`), the latest one plays on. A version posted whole to its node (the offline engine of the specs, bench-osc) is copied in at once.
- Through `osc_command` go the options of a voice (table ids interned per scope, the 8 random shares of each oscillator drawn by the facade in the order of the TS, then its `UnisonShape` and, for a random detune, 8 more), its routes (param names as ids, 7 values each: source, param, amount, min, max, scale, bipolar; the oscillators ids 0–11, position, spread, gain, pitch, fine, blend each; the filter 12–14, the knobs of the LFOs 15–34), its filter, its velocity and the states of the LFOs (`setLfos` of the shared: the tables, then the knobs and the anchors); the 12 params of a block through `osc_io` (one value or `frames`), the outputs through `osc_io_output`. `voices-processor.ts` is the voices processor of the worklet: the events of `processorOptions.events` before its first block, those of its port in order, a report after a block that has one; `tap` puts voice k in channels 2k and 2k + 1.
- The render loops wrap the phase in a cold call (else LLVM makes the wrap a select on the chain of the phase, a third slower); two neighbouring unison voices that both play their mixes render in one loop (`render11_pair`; their builds are decided first, in their order, so the budget and the counters stay the same); a voice that fades from a frame into another reads both in loops of their own (`render21_same` on one level; `render22_same` on two of one length, the four windows in the lanes of an f32x4; `render22` on two of other lengths); `render_fade`, which calls them, is not inlined (inlined into `render_voices` with `render_span`, the loops of a frame alone, it cost a voice held on its mix table 5%: its registers). Frames are read through windows checked once per span, a mix is built over slices checked once (a check per read made the Lagrange upsampling a quarter slower).
- The specs of the oscillator: `wavetable-osc-dsp.spec` and `wavetable-osc-budget.spec` (`test-utils/voice-dsp.ts`: a scope of voices of one instance of the core per spec file), `wavetable-osc-goldens.spec` (scopes of voices on a store and a shared, the envelopes curved as the app gives them; each scenario again as the voices of one node, the params as the arrays of each block through `osc_scope_direct`, every voice tapped: the same hash, and the sum of a block the f32 sum of the voices in their order, its own golden `<scenario>: the sum of one node`; random scopes both ways, and with a voice that traps), `wavetable-osc-scope.spec` (the timelines against the formulas of the spec through a voice, bit for bit; the order, the sum, the reports, a trap), `wavetable-osc.worklet.spec`, `wavetable-memory.spec` and the chunks of `wavetable-builder.spec`.
- An effect core: `fx_new(rate) → handle`, `fx_buffers(handle, frames)` (inL, inR, outL, outR in its memory, grown before the block), `fx_process(handle)`, `fx_clear(handle)` (a `{ clear }` message of `registerStereoProcessor`), `fx_free(handle)` (`stereo-processor.ts` frees it on `stop`); `stereoCore` keeps Float32Array views on the memory, made again when it grew (`createView` of `wasm-core.ts`; a pointer comes as an i32 and is read unsigned: past 2 GiB it is negative). The options of `fx_new` and the messages go through `fx_command` (a Float64Array in its memory): the reverb's `fx_set(handle, routed)` reads a count and key/value pairs (one `set`: the line scale follows once), the distortion's a bitmask of the keys present and the params; `fx_set_active`, `fx_idle`. Allocations only in constructors and when a buffer grows, never in a block.
- The functions of a core compile lazily, on their first call (the first block of a voice 0.93 ms in Node, then 0.014): each worklet module renders a few blocks of its own dsp while it loads and frees it (`prewarmStereo` of an impulse, over the ceiling of the limiter; the distortion both curves; the oscillator a voice of both oscillators on the placeholder sine and a table of 2 frames of silence (`createLevels(2, 32)`: the fades of a frame at the pitches of their three loops), with a store and a shared of its own, a route of LFO 1 and routes to its knobs (a flat block in its Delay, a new Phase gliding, a new shape crossfading), a moving position, then a steady one), so neither the constructor nor the first block of a processor compiles them (the oscillator's prewarm takes 2 ms, before the first note).
- The distortion and the reverb take NaN and the infinities as 0 (`finite_inputs` of the stereo io before a block, a finite input to the bit); a block whose peak isn't a float clears the state and is silence; `wav.ts`, the decoded files and the worker take such samples as 0 too (the native delay holds a NaN in its loop in Chromium and WebKit). The fuzzers of the effects keep to what the app sends them (NaN, the infinities and 1e30 in their input; the params in their ranges, beyond the top only where the core stays finite: a decay or a bass beyond its range blows the loops up, the knobs and the modulation never go there).

### Snapshots

`apps/chisper/src/app/app/plugins/snapshot.ts` creates one `searchParamsSnapshotPlugin`. Models that register it (`osc1`, `osc2`, `filter`, `env`, `mod`, `fx`, `lfo`, synth as `v`) expose their state as `{ [modelName]: { key: value } }`:

- `getSnapshot()` / `applySnapshot(obj)` read and apply the state at runtime (used by presets); `$snapshotChanges` emits on any change.
- Legacy URL params `<modelName>-<key>=<json>` are still applied on init.
- `applySnap` must handle falsy values (`!== undefined`, not `&&`), and missing keys mean defaults.
- When adding persisted state, extend the model's `modelToSnap`/`applySnap` **and** `presetDataSchema` in `libs/preset-schema` (unknown keys are stripped, so a missing schema field is silently not saved). A new field changes the hash of every preset: the presets of the database get it by a migration after the deploy, not by legacy code.
- Oscillator keys: `o`, `s`, `f` Oct, Semi and Fine (whole octaves ±3, semitones ±24 `SEMI_MAX`, cents ±100 `FINE_MAX`; missing: 0), `d` the unison detune (its spread), `b` its blend (0..1, 0.75 by default as the init patch of the reference AU; missing: 0.75), `w` the Wave position in the frames played (fractional; of a table with a morph mark among its 256), `ph`/`pr` Phase and Phase rand (0..1, default `DEFAULT_PHASE` 0.5 = 180° and 1). A legacy `r` (Phase rand as a start delay of 0..2 ms) is read only: without `pr` it becomes `pr = min(1, r / 0.002)` (`withLegacyPhase`, in the schema; `applySnap` calls it for legacy urls), never written; such a legacy preset or url without `ph` gets `LEGACY_PHASE` 0 (it played from the start of the wave).
- LFOs `lfo`: `l1`–`l4`, each `rate` (the period, seconds), `delay`, `rise`, `smooth`, `phase`, `shape`, `mode`, optional `points`, and its tempo: `bpm` (false: HZ), `div` (1/4), `trip`, `dot`, `host` (true), `delayDiv`, `riseDiv` (Off; indexes into `TEMPO_DIVISIONS`, the schema puts each within the steps of its knob).
- The delay of `fx`: `time` (seconds, MS) and its tempo `sync` (0: MS), `div` (1/8), `trip`, `dot`, numbers as its other params (0/1, an index into `TEMPO_DIVISIONS`).
- Voicing `v`: `leg`, `port`, `max` and the range of the pitch bend `bd`/`bu` (semitones 0..24, 2 by default; those of a url snapshot whole within it, one that isn't a number the default: `bendRangeFrom`, Infinity would bend by NaN cents). Envelopes `env`: `e1`–`e3` (each with `bpm`, false: MS, and `divs` of its times, `ENVELOPE_DIVISIONS`: the nearest to its seconds at 120) and the velocity `vel` (`amp`, `k`; a fresh preset and Init: Amp 1, a line).
- Routes `mod`: `<source>:<knob>` with the sources `env1`–`env3`, `velo`, `lfo1`–`lfo4`; a number is a route on, `{ a, bi: true }` bipolar, `{ a, off: true }` (with `bi` too) switched off.

### Presets (apps/chisper/src/app/presets, netlify/functions)

- `libs/preset-schema`: zod schema of preset data with ranges and defaults, `normalizePreset` (4 significant digits, sorted keys), `presetHash` (sha256 of normalized JSON, name excluded → dedup), profanity filter. Shared by the client and functions (functions import it by relative path, esbuild doesn't know tsconfig aliases).
- API (Netlify Functions v2, routed by `config.path`): `presets.mts` handles `/api/presets` (list/search with keyset cursors, save with Turnstile + 5/hour/IP), `/api/presets/top`, `/api/presets/:id` (GET, and PUT to overwrite), `/api/presets/:id/report`, `/api/presets/:id/opened`, `/api/presets/name-available?name=`; `usage.mts` stores listens and stays (each with a Turnstile token of its own). IPs are stored only as salted hashes.
- Scheduled: `recompute-scores.mts` (every 30 min) and `cleanup.mts` (daily: removes unqualified presets 90 days after they were saved, edited or opened by their author, `GREATEST(created_at, updated_at, author_opened_at)`; listeners not heard for 60 days; reports of hidden presets and those older than 180 days, so REPORT_HIDE_THRESHOLD counts the reports of half a year).
- Scores (`recompute-scores`, last 60 days): a listener is an `ip_hash` (`getIpHash` hashes `ipKey`: IPv4 as is, IPv6 by its /64, privacy addresses rotate), not a client id (clearing localStorage would make new ones). A listen is playing a chosen preset `USAGE_LISTEN_SECONDS` (10), a stay `USAGE_STAY_SECONDS` (60, both `libs/preset-schema`), both without switching to another one; presets skipped sooner are not counted (the top is stepped through with ◀ ▶ the most). The client sends each once a preset is opened (`POST /api/usage` `{ presetId, event: 'listen' | 'stay', turnstileToken }`); `usage.mts` keeps one `listens` row (migration 004) per preset and IP with the days of the last listen (`heard`) and stay (`stayed`, NULL if none), each renewed at most once a day; a stay sets `heard` too, so `stayed <= heard`. Listens on hidden presets and on the author's own ones (the preset's `ip_hash`) are not stored; the preset opened on start is not counted at all (its listeners didn't choose it). Each listen and stay weighs w, a 7-day half-life since its day. `score` = the share of listeners who stayed with a Bayesian prior: (Σ w stays + k·m) / (Σ w listens + k), m the site's share: Σ over all presets of their shares, each weighing min(Σ w listens, k), k = SCORE_PRIOR_LISTENERS (with every listen counted the top would make the average itself and its lower part would keep falling below it); a share, not a count, so the top's extra traffic (start, ◀ ▶) gives it no extra score, and a preset with few listeners stays near m. `unique_users` = the listeners who stayed (shown in the lists). Only presets with MIN_UNIQUE_USERS of them get a score (and `qualified_at`). `cleanup` removes rows not heard for 60 days.
- Popular: `preset_scores.popular` with POPULAR_MIN_USERS listeners who stayed and a share not below m (m is a rounded numeric quotient, compared with a 1e-12 tolerance, so exactly the average counts): the bar doesn't grow with the audience. `/api/presets/top` (Popular tab, ◀ ▶, 50 presets) has every featured preset first (curated, `presets.featured`, whatever its score), then such presets by score; the `popular` sort of the list orders all presets by score, whatever the threshold.
- Client: `presets` rxModel (current preset, dirty flag via hash comparison, ◀ ▶ list, `?preset=<id>` loading; a preset and Init are applied through the sound switch, its `setCurrent` too (a preset that throws as it is applied: a toast, it doesn't become current), the restore of the tab at once; specs without the synth pass `immediateSoundSwitch` of test-utils), `usePresetUsageTracker` (counts the seconds an opened preset is played: audio runs, the tab is visible and a note is held or was played or released in the last 30 s; once a preset reaches `USAGE_LISTEN_SECONDS` / `USAGE_STAY_SECONDS` without switching it reports the listen / the stay, each once; the `auto` preset is not counted until it is chosen; another preset drops a listen or stay not reached, a hidden tab only pauses it), `UsageReporter` (rendered by `PresetSection`) sends them one at a time, each through a Turnstile widget of its own (`appearance: 'interaction-only'`, out of the layout, the script loads with the first event): the visitor never sees it; an event Cloudflare would ask to interact for, a failed check or no token in `CAPTCHA_TIMEOUT_MS` (30 s) is dropped.
- Start without `?preset=`: `openPopular` opens a random one of `/api/presets/top` as `auto` (unless something was loaded, saved or changed meanwhile: the state must still hash to `presetHash({})`). Random, not the first: no single preset is opened for every visitor; ▶ continues from it. An `auto` preset is not put in the url (after a reload it would open from the link as chosen). Init (the button between the name and ▶, `reset`) applies `normalizePreset({})` (not `applySnapshot({})`: some `applySnap` keep missing keys), clears the preset and the url. The tab keeps what a reload would lose (sessionStorage `presetState`: the current preset, its loaded hash and the params, written 200 ms after a change and on `pagehide`): an edited preset, the `auto` one, an edited Init; not a clean preset (its link opens it) nor Init itself (the start opens a popular one). On start it is applied (through `normalizePreset`) instead of loading when its preset is the one of the url (none for `auto` and Init), so a link to another preset in the same tab opens that one. UI: `PresetPanel` in the header, `PresetBrowser` and `SaveDialog` antd modals. Cmd/Ctrl+S opens the save dialog.
- Editing: on create the server returns a secret `editToken` (only its sha256 is stored in `presets.edit_token_hash`); the client keeps tokens in `localStorage.presetEditTokens`. `PUT /api/presets/:id` with the token overwrites sound and name (no Turnstile, 1 update per 5 s, 409 if the sound is another preset's). Presets created before migration 002 have no token and can't be edited. Opening an own preset (`applyPreset` with a token in `localStorage`, once a session) posts the token to `POST /api/presets/:id/opened`, which sets `presets.author_opened_at` (migration 005, at most once a day, a wrong token changes nothing): the author keeps it from the cleanup.
- Names are unique case-insensitively with collapsed whitespace (`presetNameSchema` normalizes, `presets_name_key` is a unique index on `lower(name)`, migration 003). Hidden presets keep their names. The save dialog checks availability while typing; saving the same sound under a taken name still returns the existing preset (dedup by hash comes first).

### Wavetables

- The Netlify functions (`netlify/functions/get-wavetables-list.ts`, `get-wavetable.ts`) list the wavetable files in an S3 bucket as a folder tree and serve them. The client fetches the list with react-query (`synth/oscillator/hooks/use-wavetables.ts`). The table itself is loaded by the oscillator model from `$waveTablePath` (last path element = S3 key, `synth/services/wavetable.ts`, cached per session, 2 retries), so it follows presets whatever screen is shown; `WaveSelector` only shows `$waveTableLoading`.
- The files are wavetables in mono 32-bit float WAV (44.1 kHz, 2048-sample waves, 256 at most: the manual editor adds no wave to a table of 256), most of them with a mark (the `clm ` chunk, `<!>2048 10000000 …`: the samples of a frame, then flags). A mark whose first flag is not 0 is a morph: the table plays expanded to 256 frames by crossfades, whatever that flag: frame j of N at round(j·255/(N−1)), between two the next one weighs (i + 1)/(s + 1) at i frames into a span of s (`wavetable-frames.ts`, checked against `dsp/measurements/frames.json`; the second flag changes nothing it plays). `synth/services/wav.ts` reads their samples and the mark from the bytes (`loadWavetable` gives `{ frames, morph }`); not `decodeAudioData`, which resamples to the context rate (at 48 kHz a 2048-sample slice is 1.09 cycles and a table has ~278 waves instead of 256).
- The wavetable editor (`synth/wave-table-editor/`) also builds tables from manual drawing or from an uploaded audio file. `synth/services/audio-file.ts` reads that file at its own rate, never at the context's: a WAV through `wav.ts`, other formats decoded by an `OfflineAudioContext` at 44.1 kHz (their rate is unknown before decoding).

### Libs

Libs are imported through the path aliases in `tsconfig.base.json`: `@chisper/math`, `@chisper/rxjs-react`, `@chisper/ui-kit` and `@chisper/preset-schema`.

- `math`: number, vector and typed-array helpers, plus FFT-based wave utilities.
- `ui-kit`: styled-components UI widgets (charts, knobs/handles, piano, the pitch wheel, analysers, ADSR, the curve of the velocity) and `theme`/`GlobalStyle`. The app also uses antd 6, themed in `app/index.tsx`.
- `Handle` (a knob) and `Fader`: `onActiveChange` tells a control is held (a press, `trackPointer`, is let go too when its pointerup is lost: the window's blur, a move without a button); `name` (the full name of what it changes, 1–2 short words, before the value in the tooltip while held, `ValueTooltip`; a string `label` by default; the fader's accessible name; the FX knobs have it in their `FxParamDef`); a tooltip that doesn't fit the viewport on one line (a knob at its edge) stacks the name over the value (`NARROW_ATTR` of `Tooltip`, until it hides) and, if it still doesn't fit, moves inside it, 4 px from the edge; `mode` linear, log or pow (`valueScale`); `wrap` (a knob around a cycle, the Phase of an LFO: its mark and the arc of a route go around the travel, not clamped); `modTarget` (the drop target of `startModDrag`, none while disabled).
- Their look: a mark shows the value (a dot at the edge, 2 px, 3 px on a large knob). A knob that takes modulations (it gets a `modulations` array, maybe empty) has a translucent grey ring of 6 px on its edge for its travel; one that takes none a grey arc of 2 px for its travel 2 px out of the knob (`sizes[size].arc`, under the knob's shadow) with a green fill from `fillFrom` (min by default) to the value. The fader has a scale (`scaleTicks`: dots every 10%, short lines at 0, 50, 100% and `fillFrom`).
- `modulations`: only the `selected` route shows an arc of the color of its source over the whole ring of a knob, or a bar as wide as the slot beside a fader. A control with routes has an `AmountDot` (`RoutesDot`), 14 px: an equal section of the color of each route clockwise from the top (an SVG of `arc`s: jsdom drops a conic-gradient) with a sine over them, stuck to the outer edge of the knob's ring at the top left (above the top left of a fader), a hit area of 20 px; with a `selected` route drag it to change the amount (steps of 1%), a long press opens the menu of the control (a route is removed only there, its ×); without one it only shows the routes, a press on it goes to the control (`passive`; a fader drags from it relative to its value). It takes no focus (a press keeps it where it was: B, the key of a note, switched the polarity of a dot left focused). A route switched off (`off`) is faded on the dot, the arc and the bar (`OFF_OPACITY`).
- `useModMark`: a mark like the knob's or the fader's value line, at 0.5 opacity, where the sum of amount × level of the live routes moves it, painted on a canvas of the control (rendered while a route is live) every frame it moved, without a render. `useLiveDraw(knobs, draw, active)` draws a chart of knobs the same way: at once, again when its knobs or `draw` change, and in every frame the routes moved a knob in, at most every `MIN_FRAME_MS` (12 ms: every other frame at 120 Hz), at the values they move them to (`routedShare` of `mod-routes.ts`); its lines are on a canvas over the chart (`useLiveLine` on `useLiveCanvas`, in the `overlay` of `LineChart`; `useCanvas`, the marks' too: at the pixel ratio of the screen, `usePixelRatio`, one query for every control; the miter of an svg stroke, `strokePath`), from typed arrays (`responseInto`, `transferCurve`, `decayCurve`, `periodPoints`: the lowest and the highest sample of each pixel column past 2 per column) mapped by the d3 scales as `affine` k·v + b to 0.1 px, drawn again only when a point moved that much (or the canvas was cleared: a new size, ratio or padding). What moves every frame draws on a canvas, never in the DOM: in Chrome a path whose `d` changes every frame paints the whole document and lays out its svg, an element moved by its transform (`will-change` too) restyles and layerizes the page, a mark without a layer of its own rasters its tiles; the compositor takes a canvas drawing as it is (`scripts/wasm-browsers/app.mjs` checks it).
- `DragValue` (the strips of the oscillator) takes `modulations` and `modTarget` too (Semi, Fine): a line of 4 px along its bottom, as wide as it, its range (the value at its share, an amount a share of it as of a knob), the bar of the selected route on it from the value up to an end, the mark a light dot as high as the line on a canvas over it; the dot of the routes right of the value, in a place of its own kept without routes (the value doesn't move when the first one comes). `DraggableNumber` (Poly, the range of the bend): a step every 10 px dragged up.
- `SwitchKey` (BPM, the triplets: a key lit while on) takes no focus (`tabIndex` −1, a press keeps it where it was: the keys stay those of the notes) and shows the antd `Tooltip` of the header once hovered `SWITCH_KEY_TIP_DELAY` (700 ms), not a `title`: its `name`, its `hint`, disabled its `disabledHint` (why), on a wrapper (a disabled button takes no mouse events). `SwitchKeys` puts keys on one plate (`stack`: the first across the top, the others in a row under it; `disabled`: all of them off, faded as a whole, its `disabledHint` in their tooltips).
- The menu of a control (`control-menu/`, `useControlMenu`: `Handle`, `Fader`, `DragValue`, `DraggableNumber` with a `defaultValue` or `modulations`, each follows its presses by its `track`): a right click, Ctrl+click and Android's long press, a long press of a finger or a pen (500 ms within 3 px: a finger moves a control only past 3 px, a tap on the track of a fader jumps there), a long press on the dot of the routes. A portal under the control (over it where it doesn't fit, within 8 px of the edges): its name and value, a row of each route (its source and amount, dragged as a value of a strip: right or up raises the amount, `AMOUNT_TRAVEL` px from −100% to +100% as its dot, a line under them shows it from its middle; Uni | Bi, a `Lamp` on/off, remove), Default (`defaultValue` within min..max; the app's from `PRESET_DEFAULTS` of the schema, `presetDataSchema.parse({})` (`OSC_DEFAULTS` of both oscillators), and its constants: Mix per effect, Rate as the frequency of the period, Master 0 dB) and Clear modulation (`onClearModulations`, with a route at least). Closed by a press out of it, Escape, a scroll, a resize, the blur of the window; it takes no focus, its events stay in it (React bubbles them through the portal to the control).
